### 1.2 AI Chat ต่างจาก AI Agent อย่างไร

นี่คือเส้นแบ่งที่ผู้เรียนต้องแยกให้ออกตั้งแต่นาทีแรก

```
AI Chat (สิ่งที่คนส่วนใหญ่ใช้):        AI Agent (สิ่งที่เราจะใช้วันนี้):
┌──────────────────────────────┐      ┌──────────────────────────────┐
│ คน  ──ถาม──►  AI            │      │ คน ──สั่ง──► AI Agent        │
│      ◄─ตอบเป็นข้อความ─       │  ⟶  │              │ วางแผน        │
│                              │      │              ▼               │
│ คนต้องเอาคำตอบไปทำเองต่อ      │      │        เรียกเครื่องมือจริง    │
│ (copy-paste, กดปุ่มเอง)      │      │        อ่านไฟล์ / รัน คำสั่ง  │
│                              │      │        ยิง API / เขียนโค้ด    │
└──────────────────────────────┘      └──────────────────────────────┘
   ได้ "คำตอบ"                            ได้ "ผลลัพธ์ที่เกิดขึ้นจริง"
```

| ประเด็น | AI Chat | AI Agent |
| --- | --- | --- |
| ผลลัพธ์ | ข้อความ | การกระทำจริงในระบบ |
| เข้าถึงไฟล์ในเครื่อง | ไม่ได้ | ได้ |
| รันคำสั่ง / ติดตั้ง package | ไม่ได้ | ได้ |
| เรียก API ภายนอก | ไม่ได้ (เว้นแต่มี tool) | ได้ผ่าน MCP |
| ทำงานหลายขั้นต่อเนื่อง | ต้องบอกทีละขั้น | วางแผนเองแล้วทำต่อกันได้ |
| ตัวอย่าง | Claude.ai, ChatGPT บนเว็บ | **Claude Code**, **GPT Codex CLI** |

> ✅ **ประโยคสรุปที่ใช้อธิบายให้ผู้บริหารฟังได้:** AI Chat คือ "ที่ปรึกษาที่พูดเก่ง" ส่วน AI Agent คือ "พนักงานที่ลงมือทำได้จริง" และ MCP คือ "ใบอนุญาตพร้อมกุญแจ" ที่เราให้พนักงานคนนั้นเข้าไปทำงานในระบบของเรา

### 1.3 Model Context Protocol (MCP) คืออะไร

ปัญหาก่อนมี MCP คือ AI แต่ละตัวต่อกับระบบภายนอกด้วยวิธีของตัวเอง ถ้ามี AI 3 ตัวและระบบ 5 ระบบ ต้องเขียนตัวเชื่อม 15 ชุด

```
ก่อนมี MCP (N x M):                    หลังมี MCP (N + M):

Claude ──┬──► LINE                     Claude ──┐
         ├──► Postgres                 Codex   ─┼──► [ MCP มาตรฐานกลาง ]
         └──► GitHub                   ตัวอื่น  ─┘          │
Codex  ──┬──► LINE                                    ┌─────┼─────┐
         ├──► Postgres                                ▼     ▼     ▼
         └──► GitHub                              LINE  Postgres GitHub
ตัวอื่น ──┬──► LINE
         ├──► Postgres
         └──► GitHub
   เขียนตัวเชื่อม 3 x 3 = 9 ชุด              เขียน MCP Server ระบบละ 1 ชุด (3 ชุด)
```

**MCP (Model Context Protocol)** คือมาตรฐานเปิดที่กำหนดว่า AI Agent จะคุยกับระบบภายนอกด้วยรูปแบบใด ทำให้ MCP Server ตัวเดียวใช้ได้กับ AI Agent ทุกตัวที่รองรับมาตรฐานนี้ (Claude Code, Codex CLI, และอื่น ๆ)

องค์ประกอบที่ต้องรู้จัก 3 อย่าง

| องค์ประกอบ | หน้าที่ | ตัวอย่างในหลักสูตรนี้ |
| --- | --- | --- |
| **MCP Host / Client** | AI Agent ที่เรียกใช้เครื่องมือ | Claude Code, Codex CLI |
| **MCP Server** | โปรแกรมที่ห่อ API ของระบบหนึ่งให้เป็นเครื่องมือมาตรฐาน | `@line/line-bot-mcp-server`, `@modelcontextprotocol/server-postgres` |
| **Tools** | ฟังก์ชันที่ MCP Server เปิดให้เรียก พร้อมคำอธิบายว่าใช้ทำอะไร | `push_text_message`, `get_message_quota` |

> 📖 **อ้างอิง:** สเปกและรายชื่อ MCP Server ที่มีอยู่ดูได้ที่ https://modelcontextprotocol.io/ ส่วนวิธีเพิ่ม MCP เข้า Claude Code อยู่ที่ https://docs.claude.com/en/docs/claude-code/mcp

### 1.4 เจาะเครื่องมือทั้ง 12 ตัวของ line-bot-mcp-server (v0.5.0)

นี่คือ "กล่องเครื่องมือ" ที่เราจะใช้ตลอดวันนี้ แบ่งได้ 3 กลุ่มชัดเจน

| กลุ่ม | เครื่องมือ | ใช้ทำอะไร | ได้ลองตอนไหน |
| --- | --- | --- | --- |
| **ส่งข้อความ** | `push_text_message` | ส่งข้อความ text ถึง user หรือ group ที่ระบุ | Workshop 1 ขั้นที่ 1 |
| | `push_flex_message` | ส่ง Flex Message ถึง user หรือ group | Workshop 1 ขั้นที่ 5 |
| | `broadcast_text_message` | ส่ง text ถึงผู้ติดตาม OA ทุกคน | Workshop 1 ขั้นที่ 4 |
| | `broadcast_flex_message` | ส่ง Flex ถึงผู้ติดตามทุกคน | โจทย์ท้าทาย |
| **ข้อมูล** | `get_profile` | ดึงชื่อและรูปโปรไฟล์ของ user | Workshop 1 ขั้นที่ 2 |
| | `get_follower_ids` | ดึงรายชื่อ userId ของผู้ติดตามทั้งหมด | Workshop 1 ขั้นที่ 2 |
| | `get_message_quota` | ตรวจโควต้าข้อความคงเหลือของเดือนนี้ | Workshop 1 ขั้นที่ 3 |
| **Rich Menu** | `get_rich_menu_list` | ดูรายการ rich menu ที่มีอยู่ | Workshop 2 ข้อ B1 และ B5 |
| | `create_rich_menu` | สร้าง rich menu ใหม่ **พร้อมสร้างภาพ อัปโหลด และตั้งเป็น default ให้ในคำสั่งเดียว** | Workshop 2 ข้อ B3 |
| | `delete_rich_menu` | ลบ rich menu | Workshop 2 ข้อ B6 |
| | `set_rich_menu_default` | ตั้งเป็นเมนูหลักของบัญชี (ใช้เมื่อต้องสลับกลับไปเมนูเก่า) | Workshop 2 ข้อ B6 |
| | `cancel_rich_menu_default` | ยกเลิกเมนูหลัก (ต้องทำก่อนลบเสมอ) | Workshop 2 ข้อ B6 |

> ⚠️ **สังเกตให้ดี: ไม่มีเครื่องมือใดใน 12 ตัวนี้ที่อ่านประวัติแชทได้เลย** จำประโยคนี้ไว้ให้แม่น เพราะมันคือโจทย์ทั้งหมดของวันที่ 2

### 1.5 ข้อจำกัดสำคัญ 2 ข้อที่ต้องรู้ก่อนออกแบบระบบ

#### ข้อจำกัดที่ 1: LINE Messaging API อ่านแชทย้อนหลังไม่ได้

### 2.5 ลงทะเบียน LINE Bot MCP เข้ากับ Claude Code

**Windows (Command Prompt)** - เครื่องหมาย `^` คือการขึ้นบรรทัดใหม่ของคำสั่งเดียวกัน

```cmd
claude mcp add line-bot ^
  -e NPM_CONFIG_IGNORE_SCRIPTS=true ^
  -e CHANNEL_ACCESS_TOKEN=โทเคนของคุณ ^
  -e DESTINATION_USER_ID=userIdของคุณ ^
  -- npx -y @line/line-bot-mcp-server
```

**macOS / Linux** - เปลี่ยน `^` เป็น `\`

```bash
claude mcp add line-bot \
  -e NPM_CONFIG_IGNORE_SCRIPTS=true \
  -e CHANNEL_ACCESS_TOKEN=โทเคนของคุณ \
  -e DESTINATION_USER_ID=userIdของคุณ \
  -- npx -y @line/line-bot-mcp-server
```

**แกะคำสั่งทีละส่วน**

| ส่วน | ความหมาย |
| --- | --- |
| `claude mcp add line-bot` | เพิ่ม MCP Server ชื่อเล่นว่า `line-bot` (ชื่อนี้ใช้อ้างใน prompt ได้) |
| `-e NPM_CONFIG_IGNORE_SCRIPTS=true` | สั่ง npm ข้าม post-install script ทำให้ติดตั้งเร็วขึ้นและปลอดภัยขึ้น |
| `-e CHANNEL_ACCESS_TOKEN=...` | กุญแจที่ MCP ใช้ยิง Messaging API |
| `-e DESTINATION_USER_ID=...` | ปลายทางเริ่มต้นเมื่อ prompt ไม่ได้ระบุปลายทาง |
| `-- npx -y @line/line-bot-mcp-server` | คำสั่งจริงที่ใช้รัน MCP Server (`--` คือเส้นแบ่งระหว่าง option กับคำสั่ง) |

> 💡 **เกร็ดที่มีประโยชน์มาก:** ถ้าเพิ่ม MCP แล้วเปลี่ยนโฟลเดอร์แล้วหาย เพราะค่าเริ่มต้นผูกกับโฟลเดอร์ ให้เพิ่ม `-s user` ต่อท้ายชื่อ (เช่น `claude mcp add line-bot -s user ...`) จะใช้ได้ทุกโฟลเดอร์ในเครื่อง

> 3. OA ที่เพิ่งสร้างจะมีผู้ติดตามแค่ตัวเราคนเดียว **ถือว่าปกติ** ไม่ใช่ error

### ขั้นที่ 5 - Flex Message ประกาศรับสมัครงานภายใน (`push_flex_message`)

**Flex Message คืออะไร:** คือข้อความที่จัดวางองค์ประกอบเองได้ (กล่อง ข้อความ รูป ปุ่ม) ส่งเป็น **JSON** ไม่ใช่ HTML โครงสร้างหลักมี 4 ส่วน

```
bubble (การ์ด 1 ใบ)
├── header   ส่วนหัว (มักใส่สีพื้นหลังแบรนด์)
├── hero     รูปภาพใหญ่ (ไม่บังคับ)
├── body     เนื้อหาหลัก (box ซ้อน box ซ้อน text)
└── footer   ปุ่มหรือข้อความปิดท้าย

carousel = เอา bubble หลายใบมาเรียงกันเลื่อนซ้ายขวาได้ (สูงสุด 12 ใบ)
```

**Prompt**

```
ช่วยออกแบบและส่ง Flex Message ประกาศรับสมัครงานภายใน (internal job posting) เข้า LINE ให้ผม
รายละเอียด
- ตำแหน่ง: หัวหน้าแผนกคลังสินค้า สาขาขอนแก่น
- คุณสมบัติ: ประสบการณ์คลังสินค้า 3 ปีขึ้นไป, ใช้ Excel ได้ดี, ขับรถยนต์ได้
- ปิดรับสมัคร: 20 สิงหาคม 2569
- ติดต่อ: ฝ่ายบุคคล เบอร์ภายใน 101
ดีไซน์: bubble ขนาด mega ส่วนหัวพื้นหลังสีเขียว LINE (#06C755) ตัวอักษรขาว
ในเนื้อหาแสดงคุณสมบัติเป็นรายการ มีปุ่มด้านล่างข้อความ "สมัครตำแหน่งนี้"
ที่ลิงก์ไปยัง https://www.itgenius.co.th
altText ให้เป็น "ประกาศรับสมัครงานภายใน: หัวหน้าแผนกคลังสินค้า"
```

> 🎓 **จุดสอน 3 ข้อ:**
> 1. Flex Message คือ **JSON** โครงสร้าง box/text/button ไม่ใช่ HTML และไม่มี CSS
> 2. `altText` **จำเป็นเสมอ** เพราะเป็นข้อความที่แสดงใน notification และในรายการแชท ถ้าตั้งไม่ดีผู้รับจะไม่รู้ว่าข้อความเรื่องอะไร
> 3. ปุ่มแบบ `uri` ต้องเป็น **https เท่านั้น** ถ้าใส่ http จะ error ทันที

**โครงสร้าง JSON ตัวอย่างที่ AI ควรสร้างให้ (ย่อ)**

```json
{
  "type": "bubble",
  "size": "mega",
  "header": {
    "type": "box",
    "layout": "vertical",
    "backgroundColor": "#06C755",
    "paddingAll": "16px",
    "contents": [
      { "type": "text", "text": "ประกาศรับสมัครงานภายใน", "color": "#FFFFFF", "weight": "bold", "size": "lg" }
    ]
  },
  "body": {
    "type": "box",
    "layout": "vertical",
    "spacing": "md",
    "contents": [
      { "type": "text", "text": "หัวหน้าแผนกคลังสินค้า สาขาขอนแก่น", "weight": "bold", "wrap": true }
    ]
  },
  "footer": {
    "type": "box",
    "layout": "vertical",
    "contents": [
      {
        "type": "button",
        "style": "primary",
        "color": "#06C755",
        "action": { "type": "uri", "label": "สมัครตำแหน่งนี้", "uri": "https://www.itgenius.co.th" }
      }
    ]
  }
}
```

> LINE Rich Menu API ตัวเต็มรองรับ **สูงสุด 20 พื้นที่ (areas)** และให้เรากำหนดพิกัด `bounds` ของแต่ละพื้นที่เองได้อิสระ แต่ `create_rich_menu` ของ MCP ตัวนี้จำกัดไว้ที่ **6 actions** และไม่เปิดให้กำหนดพิกัดเลย
>
> **นี่ไม่ใช่บั๊ก แต่คือการออกแบบ** ผู้พัฒนา MCP เลือกตัดความยืดหยุ่นทิ้งเพื่อแลกกับความง่าย เพราะเป้าหมายคือให้ AI สั่งงานได้จบในคำสั่งเดียวโดยไม่ต้องคำนวณพิกัด
>
> **บทเรียนที่ใช้ได้กับ MCP ทุกตัว:** อย่าเดาว่า MCP ทำได้ทุกอย่างที่ API ต้นทางทำได้ ให้เปิดดู **รายการ input จริงของ tool** ก่อนออกแบบงานเสมอ ไม่งั้นจะเสียเวลาเขียน prompt สั่งสิ่งที่ tool ไม่มีทางรับได้
>
> **ตรวจได้จากไหน:** ดูที่ README ของ MCP ตัวนั้น (https://github.com/line/line-bot-mcp-server) หรือถาม AI ตรง ๆ ว่า "tool `create_rich_menu` รับ input อะไรบ้าง" ซึ่ง AI อ่านได้จาก schema ที่ MCP ประกาศไว้

**ถ้าอยากได้เมนูเกิน 6 ปุ่ม หรืออยากคุมดีไซน์ภาพเอง ต้องทำอย่างไร**

| ความต้องการ | ทำผ่าน MCP ตัวนี้ได้ไหม | ทางออก |
| --- | --- | --- |
| เมนู 1-6 ปุ่ม ภาพอัตโนมัติ | ได้ | ใช้ `create_rich_menu` (สิ่งที่เราทำใน Part B) |
| เมนูเกิน 6 ปุ่ม | ไม่ได้ | ใช้ `richmenuswitch` ทำเมนูหลายชั้น หรือเขียนโค้ดเรียก LINE API เอง |
| ภาพดีไซน์ตามแบรนด์เอง | ไม่ได้ | ต้องสร้าง rich menu ใบใหม่ด้วย LINE API ตรง ๆ แล้วอัปโหลดภาพเอง (สอนใน **Part D**) |

### Part B: สร้าง Rich Menu เมนูบริการพนักงาน (20 นาที)

#### B1. ดูของเดิมก่อน (`get_rich_menu_list`)

```
ช่วยแสดง rich menu ทั้งหมดที่มีอยู่ใน LINE OA ของผม ถ้าไม่มีให้บอกว่าไม่มี
```

#### B2. ออกแบบเมนูบนกระดาษก่อน 3 นาที (ยังไม่ต้องแตะคีย์บอร์ด)

> 🎓 **ทำไมต้องมีขั้นนี้:** เพราะ tool รับได้แค่ **6 ปุ่ม** และ `create_rich_menu` จะ **ตั้งเป็นเมนูหลักทันทีที่สร้างเสร็จ** ไม่มีขั้นให้ทบทวนก่อน ถ้าไม่คิดให้จบก่อนสั่ง เราจะได้เมนูที่พนักงานทั้งบริษัทเห็นทันทีโดยยังไม่ได้ตรวจ

ให้ผู้เรียนเขียนลงกระดาษหรือ Notepad ว่าจะใส่ปุ่มอะไรบ้าง โดยตอบ 3 คำถามนี้ต่อ 1 ปุ่ม

1. พนักงานกดปุ่มนี้เพราะอยากได้อะไร
2. ควรใช้ action ชนิดไหน (`message` ให้ระบบตอบต่อ หรือ `uri` พาไปหน้าเว็บ)
3. ถ้าเป็น `message` ข้อความที่ส่งออกไปจะเอาไปทำอะไรต่อ (ตอนนี้ยังไม่มี webhook มารับ จะเห็นแค่ข้อความในแชท)

**ตัวอย่างที่เราจะใช้ในคลาส (6 ปุ่มพอดี ใช้โควตาครบพอดี)**

| ปุ่ม | `label` (ข้อความที่จะปรากฏบนภาพ) | ชนิด action | ค่า |
| --- | --- | --- | --- |
| 1 | ประกาศบริษัท | `message` | ส่งข้อความ "ดูประกาศบริษัท" |
| 2 | ขอเอกสาร HR | `message` | ส่งข้อความ "ขอเอกสาร HR" |
| 3 | แจ้งลา | `message` | ส่งข้อความ "แจ้งลา" |
| 4 | เบอร์ภายใน | `message` | ส่งข้อความ "เบอร์ติดต่อภายใน" |
| 5 | เว็บไซต์ | `uri` | https://www.itgenius.co.th |
| 6 | ติดต่อ HR | `uri` | https://line.me/R/ti/p/@itgenius |

> ⚠️ **สังเกตว่า `label` สั้นกว่าที่คนมักเขียน และนั่นตั้งใจ**
>
> `label` คือข้อความที่ถูกวาดลงบนภาพจริง และ CSS ของเทมเพลตตั้ง `word-break: break-all` ไว้ แปลว่า**ข้อความยาวจะถูกตัดขึ้นบรรทัดใหม่กลางคำแบบไม่สนความหมาย** เช่น "เบอร์ติดต่อภายใน" อาจกลายเป็น "เบอร์ติดต่อภาย" / "ใน"
>
> **กฎที่ใช้ได้จริง: `label` ควรไม่เกิน 8-10 ตัวอักษรไทย** ส่วนข้อความยาว ๆ ให้ไปอยู่ใน `text` ของ action แทน เพราะ `text` ไม่ได้ถูกวาดลงภาพ

#### B3. สั่งสร้างเมนู (`create_rich_menu`)

```
ช่วยสร้าง Rich Menu สำหรับ LINE OA ของบริษัทสยามสมาร์ทเทรด เป็น "เมนูบริการพนักงาน"
- chatBarText: "เมนูพนักงาน"
- actions ทั้ง 6 ปุ่ม โดย label ของทุกปุ่มห้ามเกิน 10 ตัวอักษร
  1. label "ประกาศบริษัท"  -> action ชนิด message ส่งข้อความ "ดูประกาศบริษัท"
  2. label "ขอเอกสาร HR"   -> action ชนิด message ส่งข้อความ "ขอเอกสาร HR"
  3. label "แจ้งลา"         -> action ชนิด message ส่งข้อความ "แจ้งลา"
  4. label "เบอร์ภายใน"     -> action ชนิด message ส่งข้อความ "เบอร์ติดต่อภายใน"
  5. label "เว็บไซต์"       -> action ชนิด uri ไปที่ https://www.itgenius.co.th
  6. label "ติดต่อ HR"      -> action ชนิด uri ไปที่ https://line.me/R/ti/p/@itgenius

ก่อนเรียก create_rich_menu ให้แสดง argument ที่จะส่งเข้า tool ให้ผมตรวจก่อน
และเตือนผมด้วยว่า tool นี้จะตั้งเมนูเป็น default ทันทีที่สร้างเสร็จ
```

> 🎓 **จุดสอนที่สำคัญที่สุดของ Workshop นี้: ตรวจ argument ก่อนกด ไม่ใช่ตรวจผลลัพธ์ทีหลัง**
>
> ให้ผู้เรียนไล่ดู argument ที่ AI แสดงออกมา แล้วตอบ 5 ข้อนี้ให้ได้ก่อนอนุมัติ
>
> | ลำดับ | สิ่งที่ต้องตรวจ | ผิดแล้วเกิดอะไร |
> | --- | --- | --- |
> | 1 | **ทุก action มี `label` และสั้นพอ (ไม่เกิน 8-10 ตัวอักษรไทย)** | `label` คือข้อความที่ถูกวาดลงภาพจริง ยาวเกินจะถูกตัดกลางคำ **ข้อนี้สำคัญที่สุด** |
> | 2 | มี action ครบตามต้องการ และไม่เกิน 6 | เกิน 6 tool ปฏิเสธทันที และจำนวนปุ่มยังกำหนดผังภาพด้วย |
> | 3 | ทุก `uri` ขึ้นต้นด้วย `https` | `http` ธรรมดาจะ error |
> | 4 | ข้อความใน `text` สะกดตรงกับที่ webhook วันที่ 2 จะรอรับ | พิมพ์ผิด 1 ตัว webhook จะจับคู่ไม่ติด |
> | 5 | `chatBarText` สั้นพอให้แสดงบนมือถือ | ยาวเกินจะถูกตัด |
>
> **ประเด็นที่ต้องย้ำในคลาส:** สังเกตว่าเราไม่ได้ตรวจว่า "ภาพสวยไหม" เพราะ MCP สร้างภาพให้เอง สิ่งที่เราตรวจได้และต้องตรวจคือ **ค่าที่ป้อนเข้า tool** ต่างหาก งานของคนในยุค AI Agent จึงย้ายจาก "ทำเอง" ไปเป็น **"ตรวจ input และอนุมัติ"**

> ⚠️ **ข้อควรระวังเรื่องฟอนต์ภาษาไทย (ให้ทดสอบก่อนวันสอน)**
>
> เทมเพลตของ MCP กำหนด font stack ไว้เป็น `'Noto Sans JP', 'IPAexGothic', 'IPAexMincho', 'Noto Sans CJK JP', sans-serif` ซึ่ง **เป็นชุดฟอนต์ญี่ปุ่นล้วน ไม่มีฟอนต์ไทยโดยตรง** ข้อความไทยจะตกไปใช้ `sans-serif` ที่เป็นค่าเริ่มต้นของเครื่อง
>
> - **บน Windows ที่มีฟอนต์ไทยครบ** โดยทั่วไปจะแสดงผลได้
> - **บน Docker หรือ Linux ที่ไม่ได้ติดตั้งฟอนต์ไทย** มีโอกาสขึ้นเป็น **กล่องสี่เหลี่ยม (tofu)**
>
> **ทางแก้ถ้าเจอปัญหา:** ใช้ `label` เป็นภาษาอังกฤษหรืออิโมจิแทน หรือข้ามไปใช้เส้นทางที่สองใน **Part D** ซึ่งเราออกแบบภาพเองได้ทั้งใบ
>
> ⛔ **สิ่งที่ทำไม่ได้:** อัปโหลดภาพใหม่ทับเมนูที่ MCP สร้างไว้แล้ว LINE กำหนดว่า **ภาพของ rich menu หนึ่งใบเปลี่ยนไม่ได้ตลอดชีพ** ถ้าอยากเปลี่ยนภาพต้องสร้างเมนูใบใหม่เท่านั้น (รายละเอียดใน Part D)

#### B4. ดูผลบนมือถือ

`create_rich_menu` ตั้งเมนูเป็น default ให้เรียบร้อยแล้ว ไม่ต้องอัปโหลดภาพเองและไม่ต้องเรียก `set_rich_menu_default` ซ้ำ

1. เปิดแชทกับบอทในมือถือ
2. **ปิดห้องแชทแล้วเปิดใหม่** (ขั้นนี้ห้ามข้าม LINE cache เมนูไว้)
3. จะเห็นเมนูโผล่ขึ้นมาด้านล่าง พร้อมข้อความ "เมนูพนักงาน" บนแถบ

ลองกดปุ่มชนิด `message` ดู จะเห็นข้อความถูกส่งเข้าแชทแทนเรา

> 💡 **สังเกตให้ดี: ตอนนี้กดแล้วยังไม่มีอะไรตอบกลับ** เพราะข้อความวิ่งไปที่ webhook ซึ่งเรายังไม่ได้สร้าง นี่คือสะพานเชื่อมไปวันที่ 2 โดยตรง พรุ่งนี้เราจะสร้างตัวรับข้อความเหล่านี้แล้วตอบกลับอัตโนมัติ

#### B5. ตรวจรายการเมนูอีกครั้ง (`get_rich_menu_list`)

```
ช่วยแสดงรายการ rich menu ทั้งหมดอีกครั้ง พร้อมบอกว่าตัวไหนเป็น default
และแสดง richMenuId ของแต่ละตัวให้ผมด้วย
```

จดค่า `richMenuId` ไว้ เพราะต้องใช้ในขั้นถัดไป

#### B6. ลบเมนูทิ้ง เพื่อฝึกวงจรให้ครบ (`cancel_rich_menu_default` + `delete_rich_menu`)

```
ช่วยยกเลิก default rich menu ก่อน แล้วจึงลบ rich menu "เมนูพนักงาน" ออกจากบัญชี
ยืนยันด้วยการแสดงรายการที่เหลือ
```

> 🎓 **จุดสอน: ลำดับสำคัญกว่าที่คิด**
>
> วงจร `create` > `cancel default` > `delete` คือ **CRUD ครบวงจร** ของทรัพยากรหนึ่งชิ้น จุดที่ต้องจำคือ **ลบเมนูที่ยังเป็น default อยู่ไม่ได้** ต้อง `cancel_rich_menu_default` ก่อนเสมอ
>
> ลองสั่ง AI ให้ลบเลยโดยไม่ cancel ก่อนดูก็ได้ จะเห็นว่า AI ที่ดีจะรู้เองว่าต้อง cancel ก่อน แต่ถ้ามันลืม เราต้องเป็นคนจับได้ นี่คือทักษะเดียวกับข้อ B3

> 💡 **ถ้าอยากเก็บเมนูไว้ใช้จริง** ข้ามข้อ B6 ไปได้เลย เมนูจะอยู่กับ OA ต่อไป แต่ถ้าตั้งใจจะทำ **Part D** (สร้างเมนูด้วยภาพของเราเอง) ต่อ แนะนำให้ทำ B6 ก่อน เพื่อไม่ให้สับสนว่าเมนูไหนเป็นตัวไหน

### Part C: Cross-check บน GPT Codex (15 นาที)

#### C1. ติดตั้ง Codex CLI

ถ้ายังไม่ได้ติดตั้งตอนเตรียมเครื่อง (ดูหัวข้อ Pre-flight Check) ให้ติดตั้งก่อนเริ่มขั้นถัดไป Codex CLI ติดตั้งได้ 4 วิธีตามระบบปฏิบัติการและเครื่องมือที่มีอยู่แล้ว เลือกวิธีใดวิธีหนึ่งก็พอ (อ้างอิง: https://learn.chatgpt.com/docs/codex/cli#getting-started)

| วิธีติดตั้ง | เหมาะกับ | คำสั่ง |
| --- | --- | --- |
| Standalone installer | macOS / Linux | `curl -fsSL https://chatgpt.com/codex/install.sh \| sh` |
| Standalone installer | Windows (PowerShell) | `powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 \| iex"` |
| npm | เครื่องที่มี Node.js อยู่แล้ว (ทุกระบบ) | `npm install -g @openai/codex` |
| Homebrew | macOS / Linux ที่ใช้ brew | `brew install --cask codex` |

อัปเดตเวอร์ชันภายหลังให้รันคำสั่งเดิมซ้ำอีกครั้ง (Homebrew ใช้ `brew upgrade --cask codex` แทน)

**หลังติดตั้งเสร็จ**

1. ตรวจว่าติดตั้งสำเร็จด้วย `codex --version`
2. เปิด Terminal ในโฟลเดอร์โปรเจกต์แล้วรัน `codex` ครั้งแรกจะให้เลือกวิธีล็อกอิน เลือก **Sign in with ChatGPT** (หรือวิธีอื่นที่รองรับ)
3. ลองพิมพ์ข้อความทดสอบ เช่น `Tell me about this project` เพื่อยืนยันว่า agent ตอบสนองได้ปกติ ก่อนไปตั้งค่า MCP ในขั้นถัดไป

> 💡 **ติดตั้งแบบไม่ต้องตอบคำถามระหว่างขั้นตอน (ใช้ในสคริปต์ตั้งเครื่องอัตโนมัติ):** ตั้งตัวแปร `CODEX_NON_INTERACTIVE=1` ก่อนรัน installer เช่น macOS/Linux ใช้ `curl -fsSL https://chatgpt.com/codex/install.sh | CODEX_NON_INTERACTIVE=1 sh` และ Windows PowerShell ใช้ `$env:CODEX_NON_INTERACTIVE=1; irm https://chatgpt.com/codex/install.ps1 | iex`

#### C2. เก็บค่าลับเป็น Environment Variable ก่อน (ทำก่อนแก้ config)

จุดต่างสำคัญจากฝั่ง Claude Code คือ **เราจะไม่เอา token ไปวางใน config ของ Codex เลย** แต่จะตั้งเป็น environment variable ระดับ User ของ Windows แล้วให้ Codex ดึงเข้าไปให้ MCP process แทน

เปิด PowerShell แล้วรัน

```powershell
setx CHANNEL_ACCESS_TOKEN "YOUR_LINE_CHANNEL_ACCESS_TOKEN"
setx DESTINATION_USER_ID "YOUR_LINE_USER_ID"
```

> ⚠️ **หลังรัน `setx` ต้องปิดแล้วเปิด PowerShell และ Codex ใหม่** ค่าถึงจะมีผล หน้าต่างที่เปิดค้างอยู่ก่อนหน้าจะยังไม่เห็นค่าใหม่ นี่คือสาเหตุอันดับ 1 ที่ตั้งค่าถูกแล้วแต่ MCP ยังหา token ไม่เจอ

ตรวจว่าค่าเข้าไปแล้วจริงโดย **ไม่ต้องโชว์ token เต็ม ๆ บนหน้าจอ** (ปลอดภัยเวลาแชร์จอสอน)

```powershell
if ($env:CHANNEL_ACCESS_TOKEN) { "CHANNEL_ACCESS_TOKEN: OK" } else { "CHANNEL_ACCESS_TOKEN: MISSING" }
if ($env:DESTINATION_USER_ID) { "DESTINATION_USER_ID: OK" } else { "DESTINATION_USER_ID: MISSING" }
```

```powershell
npx -y @line/line-bot-mcp-server
```

> 💡 **เห็นเคอร์เซอร์ค้างรออยู่ = ปกติ ไม่ใช่ error** เพราะ MCP ตัวนี้เป็นแบบ **STDIO** ที่รอรับคำสั่งทาง standard input อยู่ กด `Ctrl + C` เพื่อออกได้เลย ถ้าครั้งแรกช้า 1-2 นาทีถือว่าปกติเพราะกำลังดาวน์โหลด package

#### C4. ตั้งค่า MCP ฝั่ง Codex

Codex เก็บ config ไว้ในไฟล์ TOML ไฟล์เดียว

- Windows: `%USERPROFILE%\.codex\config.toml` (เช่น `C:\Users\Samit\.codex\config.toml`)
- macOS / Linux: `~/.codex/config.toml`

เปิดไฟล์ด้วย Notepad

```powershell
notepad "$HOME\.codex\config.toml"
```

เพิ่มบล็อกนี้เข้าไป

```toml
[mcp_servers.line-bot]
command = "npx"
args = ["-y", "@line/line-bot-mcp-server"]

enabled = true
startup_timeout_sec = 60
tool_timeout_sec = 60

default_tools_approval_mode = "prompt"

env_vars = [
    "CHANNEL_ACCESS_TOKEN",
    "DESTINATION_USER_ID"
]

[mcp_servers.line-bot.env]
NPM_CONFIG_IGNORE_SCRIPTS = "true"
```

**แกะ config ทีละบรรทัด**

| บรรทัด | ความหมาย | ทำไมต้องมี |
| --- | --- | --- |
| `command` / `args` | คำสั่งที่ใช้สตาร์ต MCP server | เทียบได้กับส่วนหลัง `--` ของ `claude mcp add` |
| `enabled = true` | เปิดใช้ server ตัวนี้ | ตั้งเป็น `false` เพื่อปิดชั่วคราวโดยไม่ต้องลบทั้งบล็อก |
| `startup_timeout_sec = 60` | รอ server สตาร์ตได้นานสุด 60 วินาที | ค่าเริ่มต้นคือ 10 วินาที ซึ่งมัก **ไม่พอ** สำหรับครั้งแรกที่ `npx` ต้องโหลด package |
| `tool_timeout_sec = 60` | รอ tool ทำงานได้นานสุด 60 วินาที | งานอย่างสร้าง Rich Menu ใช้เวลานานกว่าปกติ |
| `default_tools_approval_mode = "prompt"` | ถามอนุมัติทุกครั้งก่อนเรียก tool | **สำคัญที่สุดข้อนี้** เพราะ MCP ตัวนี้ broadcast และลบ Rich Menu ได้จริง |
| `env_vars = [...]` | รายชื่อตัวแปรที่ให้ Codex **ดึงจาก environment ของเครื่อง** ส่งเข้า MCP process | ค่าลับไม่ต้องอยู่ในไฟล์ config เลย |
| `[mcp_servers.line-bot.env]` | ตัวแปรที่เขียนค่าจริงลงไฟล์ตรง ๆ | ใช้เฉพาะค่าที่ **ไม่ใช่ความลับ** เช่น `NPM_CONFIG_IGNORE_SCRIPTS` |

> 🎓 **จุดสอนสำคัญ: `env_vars` ต่างจาก `[...env]` อย่างไร**
>
> - `[mcp_servers.line-bot.env]` = เขียนค่าจริงลงไฟล์ ใครเปิดไฟล์ก็เห็น token
> - `env_vars = ["CHANNEL_ACCESS_TOKEN"]` = เขียนแค่ **ชื่อตัวแปร** ค่าจริงอยู่ใน Windows Environment Variables
>
> ข้อดีของแบบหลัง: ไม่มี secret ใน `config.toml`, ลดโอกาสเผลอ commit token ขึ้น git, และเปลี่ยน token ได้โดยไม่ต้องแก้ config เลย

> ⚠️ **จุดพลาดที่พบบ่อย:** แก้ไฟล์ผิดที่ หรือ syntax TOML ผิด (ต้องมีวงเล็บเหลี่ยม `[mcp_servers.line-bot]` และค่าที่เป็นข้อความต้องครอบด้วย `"`) และต้องปิดเปิด codex ใหม่ทุกครั้งที่แก้ config

#### C8. Troubleshooting เฉพาะฝั่ง Codex

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
| --- | --- | --- |
| `codex mcp list` ไม่เห็น `line-bot` | แก้ไฟล์ผิดที่ หรือ syntax TOML ผิด | ดูไฟล์จริงด้วย `Get-Content "$HOME\.codex\config.toml"` ว่ามีบรรทัด `[mcp_servers.line-bot]` ไหม แล้ว restart Codex |
| แก้ไฟล์ถูกแล้วแต่ยังไม่เห็น | เครื่องนี้ตั้ง `CODEX_HOME` ไว้คนละที่ | ตรวจด้วย `echo $env:CODEX_HOME` ถ้ามีค่าเช่น `D:\codex` ไฟล์ config จริงจะอยู่ที่ `D:\codex\config.toml` ไม่ใช่ `C:\Users\<ชื่อผู้ใช้>\.codex\config.toml` |
| MCP ต่อได้แต่ไม่มี token | ตั้ง `setx` แล้วยังไม่ได้เปิด terminal ใหม่ | ปิด PowerShell และ Codex ทั้งหมด เปิดใหม่ แล้วตรวจด้วยสคริปต์ `if ($env:CHANNEL_ACCESS_TOKEN) {...}` ในข้อ C2 |
| ขึ้น timeout ตอนสตาร์ต MCP | ครั้งแรก `npx` ต้องโหลด package นาน | เพิ่ม `startup_timeout_sec = 120` ใน config |

| `node -v` ต่ำกว่า v22 | Node เก่าเกินไป | อัปเกรด Node แล้วลองใหม่ ข้อนี้เป็นสาเหตุอันดับ 1 เหมือนฝั่ง Claude Code |

```powershell
Get-Content "$HOME\.codex\config.toml"   # ดูเนื้อไฟล์ config
echo $env:CODEX_HOME                     # เช็กว่ามีการย้าย home ไหม
npx -y @line/line-bot-mcp-server         # ลองสตาร์ต MCP ตรง ๆ (Ctrl+C เพื่อออก)
```

#### C9. ทางเลือก: เพิ่ม MCP ผ่านคำสั่ง `codex mcp add`

Codex มีคำสั่งเพิ่ม MCP จาก command line เหมือน Claude Code เช่นกัน

```powershell

  --env CHANNEL_ACCESS_TOKEN="TOKEN" `
  --env DESTINATION_USER_ID="USER_ID" `
```

> ⚠️ **ทำไมหลักสูตรนี้ไม่แนะนำวิธีนี้สำหรับ token จริง:** เพราะค่าที่ส่งผ่าน `--env` จะถูกเขียนลง `config.toml` เป็นค่าจริง ซึ่งย้อนกลับไปสู่ปัญหาเดิมคือมี secret อยู่ในไฟล์ ใช้วิธีนี้ได้กับค่าที่ไม่ใช่ความลับ หรือตอนทดลองเร็ว ๆ ด้วย token ที่พร้อมทิ้ง
>
> **แนวทางที่แนะนำยังคงเป็น:** Windows Environment Variables + `env_vars` ใน `config.toml` ตามข้อ C2 และ C4

#### C10. เกร็ดเพิ่มเติม: Rich Menu กับ Puppeteer บน Codex

ถ้าลองสั่ง `create_rich_menu` ผ่าน Codex แล้วเจอ error ว่าหา Chrome ไม่เจอ สาเหตุคือขั้นตอนสร้างภาพ Rich Menu ภายในตัว MCP ต้องใช้ Puppeteer เปิด headless browser ให้ชี้ path ของ Chrome บนเครื่องให้ชัด

```powershell
setx PUPPETEER_EXECUTABLE_PATH "C:\Program Files\Google\Chrome\Application\chrome.exe"
```

ปิดแล้วเปิด terminal ใหม่ จากนั้นเพิ่มชื่อตัวแปรเข้าไปใน `env_vars` ของ config

```toml
env_vars = [
    "CHANNEL_ACCESS_TOKEN",
    "DESTINATION_USER_ID",
    "PUPPETEER_EXECUTABLE_PATH"
]
```

ถ้ายังไม่ได้ทำงานกับ Rich Menu ฝั่ง Codex ตัดบรรทัด `PUPPETEER_EXECUTABLE_PATH` ออกได้เลย

> 💡 **เหตุผลที่หลักสูตรนี้ให้ทำ Cross-check:** เพื่อไม่ให้ผู้เรียนผูกติดกับเครื่องมือใดเครื่องมือหนึ่ง ทักษะที่แท้จริงคือ **การออกแบบ workflow และเขียน prompt** ไม่ใช่การจำเมนูของโปรแกรมใดโปรแกรมหนึ่ง เครื่องมือเปลี่ยนทุกปี แต่หลักการอยู่ได้นาน

#### D1. ข้อเท็จจริงที่ต้องรู้ก่อน

> ⛔ **ภาพของ rich menu เปลี่ยนไม่ได้ตลอดชีพ**
>
> เอกสารของ LINE ระบุไว้ตรงตัวว่า *"You can't replace an image set to a rich menu. To update your rich menu image, create a new rich menu object and upload another image."*
>
> แปลว่า **เมนูที่ MCP สร้างไว้ใน Part B เราเอาภาพไปทับไม่ได้** เพราะมันอัปโหลดภาพของมันไปแล้ว ถ้าลองอัปโหลดทับจะได้ error
>
> ```
> 400 Bad Request
> { "message": "An image has already been uploaded to the richmenu" }
> ```
>
> **ทางเดียวที่ทำได้คือสร้าง rich menu ใบใหม่ทั้งใบ** แล้วอัปโหลดภาพของเราตั้งแต่ต้น

#### D2. เตรียมภาพให้ผ่านสเปกของ LINE

ในชุดไฟล์ workshop มีภาพตัวอย่างเตรียมไว้ให้แล้วที่ `assets/LINE_Rich_Menu_HR_2500x1686.jpg`

#### D3. คำนวณ bounds ของแต่ละปุ่ม (จุดที่ MCP ทำให้เรา แต่ตอนนี้ต้องทำเอง)

เมื่อสร้างเมนูเองผ่าน API เราต้องบอก LINE เองว่า **พื้นที่ไหนของภาพกดแล้วเกิดอะไร** ด้วยพิกัด `bounds` (หน่วยเป็นพิกเซล อ้างจากมุมซ้ายบน)

สำหรับภาพ 2500 x 1686 แบ่ง 6 ช่อง (3 คอลัมน์ 2 แถว)

- ความกว้างช่องละ: 2500 ÷ 3 = **833.33** ปัดเป็น 833 และให้ช่องขวาสุดเป็น 834 เพื่อให้รวมได้ 2500 พอดี
- ความสูงช่องละ: 1686 ÷ 2 = **843**

| ช่อง | ตำแหน่ง | x | y | width | height |
| --- | --- | --- | --- | --- | --- |
| 1 | บนซ้าย | 0 | 0 | 833 | 843 |
| 2 | บนกลาง | 833 | 0 | 833 | 843 |
| 3 | บนขวา | 1666 | 0 | 834 | 843 |
| 4 | ล่างซ้าย | 0 | 843 | 833 | 843 |
| 5 | ล่างกลาง | 833 | 843 | 833 | 843 |
| 6 | ล่างขวา | 1666 | 843 | 834 | 843 |

> 🎓 **จุดสอน: นี่คือสิ่งที่ MCP "ซ่อน" ไว้ให้เรา**
>
> ใน Part B เราไม่เคยเห็นตัวเลขพวกนี้เลยเพราะ MCP คำนวณให้เบื้องหลัง พอมาทำเองถึงเห็นว่าเบื้องหลังมีงานเท่าไหร่ **การเข้าใจสิ่งที่เครื่องมือซ่อนไว้คือสิ่งที่แยกคนที่ใช้เครื่องมือเป็น ออกจากคนที่แก้ปัญหาเป็นเมื่อเครื่องมือทำไม่ได้**

#### D4. รัน 3 คำสั่งให้ครบวงจร

ทั้ง 3 ขั้นใช้ `curl` ซึ่งมีอยู่แล้วใน Windows 10/11 และ macOS ตั้งค่า token เป็นตัวแปรก่อนเพื่อไม่ต้องวางซ้ำ

```powershell
$TOKEN = $env:CHANNEL_ACCESS_TOKEN
```

**ขั้นที่ 1 - สร้างโครงเมนู แล้วรับ `richMenuId` กลับมา**

```bash
curl -X POST https://api.line.me/v2/bot/richmenu \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: application/json" \
-d '{
  "size": { "width": 2500, "height": 1686 },
  "selected": false,
  "name": "เมนูบริการพนักงาน HR",
  "chatBarText": "เมนูพนักงาน",
  "areas": [
    { "bounds": { "x": 0,    "y": 0,   "width": 833, "height": 843 },
      "action": { "type": "message", "label": "ประกาศบริษัท", "text": "ดูประกาศบริษัท" } },
    { "bounds": { "x": 833,  "y": 0,   "width": 833, "height": 843 },
      "action": { "type": "message", "label": "ขอเอกสาร HR", "text": "ขอเอกสาร HR" } },
    { "bounds": { "x": 1666, "y": 0,   "width": 834, "height": 843 },
      "action": { "type": "message", "label": "แจ้งลา", "text": "แจ้งลา" } },
    { "bounds": { "x": 0,    "y": 843, "width": 833, "height": 843 },
      "action": { "type": "message", "label": "เบอร์ภายใน", "text": "เบอร์ติดต่อภายใน" } },
    { "bounds": { "x": 833,  "y": 843, "width": 833, "height": 843 },
      "action": { "type": "uri", "label": "เว็บไซต์", "uri": "https://www.itgenius.co.th" } },
    { "bounds": { "x": 1666, "y": 843, "width": 834, "height": 843 },
      "action": { "type": "uri", "label": "ติดต่อ HR", "uri": "https://line.me/R/ti/p/@itgenius" } }
  ]
}'
```

จะได้ผลลัพธ์หน้าตาแบบนี้ ให้คัดลอกค่า `richMenuId` เก็บไว้

```json
{ "richMenuId": "richmenu-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" }
```

**ขั้นที่ 2 - อัปโหลดภาพเข้าเมนูที่เพิ่งสร้าง**

> ⚠️ **สังเกตโดเมนให้ดี ขั้นนี้ใช้ `api-data.line.me` ไม่ใช่ `api.line.me`** ทุก endpoint ที่รับส่งไฟล์ของ LINE อยู่บนโดเมนนี้ ถ้าใช้โดเมนผิดจะขึ้น 404 ทั้งที่ทุกอย่างถูก

```bash
curl -X POST https://api-data.line.me/v2/bot/richmenu/{richMenuId}/content \
-H "Authorization: Bearer $TOKEN" \
-H "Content-Type: image/jpeg" \
-T assets/LINE_Rich_Menu_HR_2500x1686.jpg
```

**ขั้นที่ 3 - ตั้งเป็นเมนูหลักของบัญชี**

```bash
curl -X POST https://api.line.me/v2/bot/user/all/richmenu/{richMenuId} \
-H "Authorization: Bearer $TOKEN"
```

จากนั้นปิดห้องแชทในมือถือแล้วเปิดใหม่ จะเห็นเมนูที่ใช้ภาพของเราเอง

> 💡 **ตรวจงานได้ด้วย MCP** กลับไปที่ Claude Code แล้วสั่ง "แสดงรายการ rich menu ทั้งหมด พร้อมบอกว่าตัวไหนเป็น default" ด้วย `get_rich_menu_list` จะเห็นเมนูที่เราเพิ่งสร้างเองอยู่ในรายการ **เครื่องมือทั้งสองเส้นทางคุยกับ OA ตัวเดียวกัน จึงใช้ร่วมกันได้**

#### D5. สรุปเปรียบเทียบ 2 เส้นทาง

| ประเด็น | เส้นทาง MCP (Part B) | เส้นทาง LINE API ตรง (Part D) |
| --- | --- | --- |
| จำนวนขั้นตอน | 1 คำสั่งภาษาไทย | 3 คำสั่ง + เตรียมภาพ + คำนวณ bounds |
| ต้องเขียนโค้ดไหม | ไม่ต้องเลย | ต้องใช้ curl หรือเขียนสคริปต์ |
| จำนวนปุ่ม | สูงสุด 6 | สูงสุด 20 |
| ผังปุ่ม | 6 แบบตายตัว | ออกแบบเองอิสระ |
| ดีไซน์ภาพ | ตายตัว พื้นส้มการ์ดขาว | ควบคุมได้ 100% |
| ความเสี่ยงฟอนต์ไทย | มี (ฟอนต์ในเทมเพลตเป็นชุดญี่ปุ่น) | ไม่มี เพราะเราทำภาพเอง |
| เวลาที่ใช้ | ไม่ถึงนาที | 10-20 นาทีรวมทำภาพ |
| เหมาะกับ | ต้นแบบ ทดลอง งานภายในที่ไม่เน้นสวย | งานจริงที่ต้องตรงแบรนด์องค์กร |

> ✅ **ข้อสรุปที่อยากให้ผู้เรียนได้กลับไป:** ไม่มีเส้นทางไหน "ถูก" หรือ "ผิด" มีแต่ "เหมาะกับงานไหน" AI Agent กับ MCP ทำให้เราไปถึงต้นแบบได้เร็วมาก แต่เมื่อถึงจุดที่ต้องการความละเอียดที่เครื่องมือไม่รองรับ **เราต้องรู้ว่าจะลงไปทำเองที่ชั้นไหน** ทักษะนี้ต่างหากที่ทำให้เราเป็นคนที่ AI แทนไม่ได้

### Part E: หลัก 6 ข้อของ prompt ที่ใช้ได้กับ AI Agent ทุกตัว (5 นาที)

| ข้อ | หลักการ | ตัวอย่าง |
| --- | --- | --- |
| 1 | **บอกบทบาทและบริบท** | "ผมเป็นเจ้าหน้าที่ HR ของบริษัทสยามสมาร์ทเทรด..." AI จะเลือกน้ำเสียงถูก |
| 2 | **ระบุผลลัพธ์เป็นข้อ ๆ** | ไม่ใช่ "ทำ Flex สวย ๆ" แต่บอกสี ขนาด ปุ่ม ให้ครบ |
| 3 | **อ้างชื่อเครื่องมือเมื่อจำเป็น** | "ส่งผ่าน `push_flex_message`" ชัดกว่า "ส่งเข้าไลน์" |
| 4 | **ขอให้แสดงก่อนลงมือ** | "ให้แสดง JSON ให้ผมตรวจก่อน แล้วจึงเรียก tool" |
| 5 | **ระบุข้อห้าม** | "ห้ามใช้ markdown ในข้อความ text", "ห้าม broadcast โดยไม่ถาม" |

**ตัวอย่างการปรับปรุง prompt จริง**

| แบบเดิม (กว้างเกินไป) | แบบที่ดีขึ้น |
| --- | --- |
| "ส่งไลน์บอกวันหยุด" | "ส่งข้อความ text เข้า LINE ถึงผม แจ้งวันหยุดพิเศษวันจันทร์ที่ 10 สิงหาคม 2569 ลงท้ายว่าฝ่ายบุคคล เขียนสุภาพไม่เกิน 5 บรรทัด ไม่ใช้ markdown" |
| "ทำ rich menu ให้ด้วย" | "สร้าง rich menu ด้วย create_rich_menu โดย chatBarText เป็น 'เมนูพนักงาน' และมี 6 actions ตามรายการนี้ ... ก่อนเรียก tool ให้แสดง argument ให้ผมตรวจก่อน และเตือนว่าเมนูจะถูกตั้งเป็น default ทันที" |

> ✅ **ประโยคที่ควรจำ:** prompt ที่ดีไม่ใช่ prompt ที่ยาว แต่คือ prompt ที่ **ไม่เหลือช่องให้ตีความผิด** และ **มีจุดให้คนตรวจก่อนลงมือ**

| --- | --- |
| `The property, 'messages[0].text', is required` | ข้อความว่าง มักเกิดตอน AI ส่ง text ที่เป็น empty string |

### A. ฝั่ง Claude Code (CLI ที่ใช้ตลอดวันนี้)

Claude Code แบ่ง MCP ออกเป็น **3 ขอบเขต (scope)** เก็บ config คนละไฟล์กัน เลือกใช้ด้วยแฟล็ก `-s` หรือ `--scope` ตอนรัน `claude mcp add`

| Scope | โหลดที่ไหน | แชร์กับทีมได้ไหม | เก็บไฟล์ที่ |
| --- | --- | --- | --- |
| **Local** (ค่าเริ่มต้น) | เฉพาะโปรเจกต์นี้ เฉพาะเครื่องนี้ | ไม่ | `~/.claude.json` (ผูกกับ path ของโปรเจกต์) |
| **Project** | เฉพาะโปรเจกต์นี้ ทุกคนที่ clone repo | ได้ ผ่าน git | `.mcp.json` ที่ root โปรเจกต์ |
| **User** | ทุกโปรเจกต์บนเครื่องนี้ | ไม่ | `~/.claude.json` (ระดับบนสุดของไฟล์ ไม่ผูกโปรเจกต์) |

รวมแล้วมี **3 วิธีหลัก** ในการเพิ่ม MCP เข้า Claude Code

1. คำสั่ง `claude mcp add` (วิธีที่ใช้ตลอดคลาสนี้ ดูตัวอย่างในข้อ 2.5)
2. แก้ไฟล์ config ตรง ๆ ด้วยมือ (`.mcp.json` สำหรับ project scope หรือ `~/.claude.json` สำหรับ local/user scope)
3. ผ่านปลั๊กอิน (plugin ที่แนบ MCP server มาให้พร้อม ติดตั้ง/ถอนปลั๊กอินก็เพิ่ม/ลบ MCP ไปด้วยอัตโนมัติ) หรือผ่าน claude.ai connector จาก Anthropic Directory

### E. เก็บ Environment Variable (ค่าลับ) อย่างปลอดภัย

หลักการเดียวกันทั้งฝั่ง Claude Code และ Codex คือ **ห้ามให้ค่าลับตัวจริงไปนอนอยู่ในไฟล์ config ที่มีโอกาสหลุดขึ้น git** ให้เก็บค่าลับไว้เป็น environment variable ระดับเครื่อง แล้วให้ไฟล์ config อ้างชื่อตัวแปรแทนการเขียนค่าจริงลงไปตรง ๆ

**ตั้งค่า Environment Variable แบบถาวรระดับ User บน Windows**

วิธีที่ 1 ใช้ `setx` ใน PowerShell (สั้นที่สุด ใช้ในคลาสนี้)

```powershell
setx CHANNEL_ACCESS_TOKEN "YOUR_LINE_CHANNEL_ACCESS_TOKEN"
setx DESTINATION_USER_ID "YOUR_LINE_USER_ID"
```

วิธีที่ 2 ใช้ .NET API ผ่าน PowerShell (เขียนอ่านง่ายกว่า เหมาะกับสคริปต์ตั้งเครื่องที่ต้องอ่านย้อนหลัง)

```powershell
[Environment]::SetEnvironmentVariable(
  "CHANNEL_ACCESS_TOKEN",
  "YOUR_LINE_CHANNEL_ACCESS_TOKEN",
  "User"
)

[Environment]::SetEnvironmentVariable(
  "DESTINATION_USER_ID",
  "YOUR_LINE_USER_ID",
  "User"
)
```

วิธีที่ 3 ผ่าน GUI: พิมพ์ "Edit environment variables for your account" ใน Windows Search แล้วเพิ่มตัวแปรใหม่ในช่อง **User variables**

> ⚠️ ตั้งค่าด้วยวิธีไหนก็ตาม ต้อง **ปิดแล้วเปิด Terminal หรือ VS Code ใหม่** ค่าตัวแปรที่เพิ่งตั้งถึงจะมีผล เพราะโปรแกรมที่เปิดค้างอยู่ก่อนหน้าจะยังไม่เห็นค่าใหม่

**ตรวจว่าค่าเข้าไปแล้วโดยไม่ต้องโชว์ token บนหน้าจอ**

```powershell
if ($env:CHANNEL_ACCESS_TOKEN) { "CHANNEL_ACCESS_TOKEN: OK" } else { "CHANNEL_ACCESS_TOKEN: MISSING" }
if ($env:DESTINATION_USER_ID) { "DESTINATION_USER_ID: OK" } else { "DESTINATION_USER_ID: MISSING" }
```

> 💡 ใช้วิธีนี้เวลาสอนหรือแชร์จอ จะได้ยืนยันว่าตั้งค่าสำเร็จโดยไม่เผลอเปิด token ให้คนทั้งห้องเห็น

**นำไปใช้กับ Claude Code**

`.mcp.json` (project scope ที่แชร์ผ่าน git) รองรับการอ้างตัวแปรแวดล้อมด้วย syntax `${VAR}` โดยไม่ต้องเขียนค่าจริงลงไฟล์เลย

```json
{
  "mcpServers": {
    "line-bot": {
      "command": "npx",
      "args": ["-y", "@line/line-bot-mcp-server"],
      "env": {
        "CHANNEL_ACCESS_TOKEN": "${CHANNEL_ACCESS_TOKEN}",
        "DESTINATION_USER_ID": "${DESTINATION_USER_ID}"
      }
    }
  }
}
```

ไฟล์แบบนี้ commit ขึ้น git ได้อย่างปลอดภัย เพราะไม่มีค่าลับอยู่ในไฟล์เลย แต่ละคนในทีมต้องตั้ง environment variable ชื่อเดียวกันบนเครื่องตัวเองก่อนเริ่มใช้งาน

> ⚠️ **ข้อจำกัดที่เจอจริงตอนสอน** — syntax `${VAR}` นี้ **Claude Code CLI แทนค่าให้ แต่ Claude Desktop ไม่แทน**
> Desktop จะส่งข้อความ `${CHANNEL_ACCESS_TOKEN}` ดิบ ๆ เข้าไปเป็น token ทำให้ LINE ตอบ `401 Unauthorized`
> ทุก Channel พร้อมกัน และ**ปิดเปิดโปรแกรมกี่รอบก็ไม่หาย** เพราะไม่ใช่ปัญหาชั่วคราวตอนเปิดโปรแกรม
>
> วิธีแยกให้ชัดว่าใช่อาการนี้ไหม: เอา token ไปยิง API ตรง ๆ ถ้าได้ `200` แปลว่า token ดี ปัญหาอยู่ที่ config
>
> ```bash
> curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $LINE_HR_TOKEN" https://api.line.me/v2/bot/info
> ```
>
> ทางแก้ที่ใช้ได้ทั้ง CLI และ Desktop ครบทุก OS คือให้ `.mcp.json` เรียก**สคริปต์ตัวกลาง**ที่อ่าน env
> เองตอนรัน แทนการพึ่ง `${VAR}` (ตัวอย่างจริงอยู่ที่ [`scripts/line-mcp.js`](../scripts/line-mcp.js) ของโปรเจกต์นี้)
>
> ```json
> "line-hr": {
>   "type": "stdio",
>   "command": "node",
>   "args": ["scripts/line-mcp.js", "LINE_HR_TOKEN"]
> }
> ```

**นำไปใช้กับ Codex CLI**

`config.toml` มี 2 ทางเลือก

1. เขียนค่าตรง ๆ ใน `[mcp_servers.<ชื่อ>.env]` (สะดวก แต่ค่าลับจะอยู่ในไฟล์ตรง ๆ ห้าม commit ไฟล์นี้ขึ้น git)
2. ใช้ฟิลด์ `env_vars` เพื่อ "ดึง" ค่าจาก environment variable ของเครื่องเข้ามาแทน โดยไม่ต้องเขียนค่าจริงลง `config.toml` เลย (**วิธีที่หลักสูตรนี้แนะนำ**)

**Configuration ฉบับสมบูรณ์ที่แนะนำสำหรับเครื่อง development**

```toml
[mcp_servers.line-bot]
command = "npx"
args = ["-y", "@line/line-bot-mcp-server"]

enabled = true
startup_timeout_sec = 60
tool_timeout_sec = 60

default_tools_approval_mode = "prompt"

env_vars = [
    "CHANNEL_ACCESS_TOKEN",
    "DESTINATION_USER_ID",
    "PUPPETEER_EXECUTABLE_PATH"
]

[mcp_servers.line-bot.env]
NPM_CONFIG_IGNORE_SCRIPTS = "true"
```

> 💡 ถ้ายังไม่ได้ทำงานกับ Rich Menu ฝั่ง Codex ตัดบรรทัด `PUPPETEER_EXECUTABLE_PATH` ออกได้เลย และถ้าเน็ตช้ามากให้เพิ่ม `startup_timeout_sec` เป็น `120`

> 🔒 **หมายเหตุด้านความปลอดภัย:** `default_tools_approval_mode = "prompt"` คือด่านสุดท้ายที่กันไม่ให้ AI เผลอ `broadcast_text_message` หรือ `delete_rich_menu` โดยเราไม่ทันเห็น สำหรับ LINE OA ที่ใช้งานจริง (production) ไม่ควรเปิดสิทธิ์อัตโนมัติทั้งหมดเด็ดขาด

> 💡 Codex กรอง environment variable ที่ชื่อมีคำว่า `KEY`, `SECRET`, หรือ `TOKEN` ออกจากคำสั่งที่ agent รันเองโดยอัตโนมัติเป็นค่าเริ่มต้น (กันหลุดไปอยู่ใน log) ปรับพฤติกรรมนี้ได้ที่ `[shell_environment_policy]` ใน `config.toml` เฉพาะกรณีจำเป็นจริง ๆ เท่านั้น

**กฎ 4 ข้อที่ใช้ได้กับทั้งสองค่าย**

1. เก็บค่าลับไว้ใน environment variable ระดับเครื่อง หรือไฟล์ `.env` ที่อยู่ใน `.gitignore` เท่านั้น ห้าม hard-code ค่าลับในโค้ดหรือใน config ที่จะ commit ขึ้น git
2. ไฟล์ config ที่แชร์กับทีม (`.mcp.json`, `.codex/config.toml` ของโปรเจกต์) ให้อ้างชื่อตัวแปรเท่านั้น อย่าใส่ค่าจริงลงไป
3. สงสัยว่าค่าลับหลุด ให้ไป Issue token ใหม่ทันทีในระบบต้นทาง (เช่น LINE Developers Console) แล้วลบค่าเก่าออกจากทุกที่ที่เคยวางไว้
4. ตอนแชร์หน้าจอสอนหรือประชุม ปิดหน้าต่างที่มีค่าลับก่อนแชร์ทุกครั้ง
