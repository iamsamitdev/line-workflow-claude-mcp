รวม prompt ทุกตัวไว้ที่เดียวเพื่อ copy ไปใช้ได้ทันที
**ใช้ได้ทั้ง Claude Code และ GPT Codex** เพราะเขียนแบบไม่อ้างชื่อเครื่องมือของค่ายใดค่ายหนึ่ง

วิธีใช้: แทนที่ข้อความในวงเล็บมุม เช่น `<groupId>` ด้วยค่าจริงของคุณ

## 1. งาน HR และประกาศภายใน (Workshop 1)

### 1.1 แจ้งนัดประชุมรายบุคคล

```
ผมเป็นเจ้าหน้าที่ HR ของบริษัท <ชื่อบริษัท>
ช่วยส่งข้อความแจ้งนัดประชุมเข้า LINE ให้ผม โดยมีเนื้อหาว่า
- เรื่อง: <หัวข้อประชุม>
- วันเวลา: <วันเวลา>
- สถานที่: <สถานที่>
- สิ่งที่ต้องเตรียม: <รายการ>
เขียนให้สุภาพ กระชับ อ่านง่ายบนมือถือ ใช้การเว้นบรรทัดแทน bullet
ห้ามใช้ markdown เพราะข้อความ text ของ LINE ไม่เรนเดอร์ markdown
```

### 1.2 ดูผู้ติดตามพร้อมชื่อ

```
ช่วยดูว่ามีผู้ติดตาม LINE OA ของผมกี่คน แสดง userId ทั้งหมด
แล้วดึงชื่อโปรไฟล์ของแต่ละคนออกมาให้ด้วย สรุปเป็นตาราง
```

### 1.3 ตรวจโควต้าก่อนส่ง

```
ตรวจโควต้าข้อความของ LINE OA ผมว่าเดือนนี้ส่งได้อีกกี่ข้อความ ใช้ไปแล้วเท่าไหร่
แล้วประเมินว่าถ้าผมจะ broadcast ถึงผู้ติดตามทุกคน จะใช้โควต้าไปเท่าไหร่ พอไหม
```

### 1.4 Broadcast ประกาศ (มีขั้นยืนยัน)

```
ช่วย broadcast ประกาศถึงผู้ติดตาม LINE OA ทุกคน
เนื้อหา: <เนื้อหาประกาศ>
ลงท้ายว่า "<ชื่อฝ่าย บริษัท>"
ก่อนส่งให้แสดงข้อความที่จะ broadcast ให้ผมอ่านยืนยันก่อน และบอกด้วยว่าจะใช้โควต้าเท่าไหร่
```

### 1.5 Flex Message ประกาศ

```
ช่วยออกแบบและส่ง Flex Message ประกาศ <เรื่อง> เข้า LINE ให้ผม
รายละเอียด
- <หัวข้อ 1>: <ค่า>
- <หัวข้อ 2>: <ค่า>
ดีไซน์: bubble ขนาด mega ส่วนหัวพื้นหลังสี <รหัสสี> ตัวอักษรขาว
เนื้อหาแสดงเป็นรายการ มีปุ่มด้านล่างข้อความ "<ข้อความปุ่ม>" ลิงก์ไป <https://...>
altText: "<ข้อความสำรอง>"
แสดง JSON ให้ผมตรวจก่อน แล้วจึงส่ง
```

## 2. Rich Menu (Workshop 2)

### 2.1 สร้าง Rich Menu 6 ช่อง

```
ช่วยสร้าง Rich Menu สำหรับ LINE OA ของ <ชื่อองค์กร> เป็น "<ชื่อเมนู>"
- ขนาด 2500 x 1686 แบ่งเป็น 6 ช่องเท่ากัน (3 คอลัมน์ 2 แถว)

- ช่องทั้ง 6 ตามลำดับซ้ายไปขวา บนลงล่าง
  1. <ชื่อปุ่ม> -> action <message/uri> <ค่า>
  ...
ก่อนสร้างให้แสดง JSON ให้ผมตรวจ และอธิบายว่าค่า bounds คำนวณมาจากอะไร
```

### 2.2 จัดการ Rich Menu

```
ช่วยแสดง rich menu ทั้งหมดที่มีในบัญชี บอกว่าตัวไหนเป็น default
แล้วตั้ง "<ชื่อเมนู>" เป็น default ยืนยันผลด้วยการแสดงรายการอีกครั้ง
```

## 3. เก็บและวิเคราะห์บทสนทนากลุ่ม (Workshop 3-4)

### 3.1 สร้าง Webhook Server

ดู prompt เต็มใน `03-Workshop-3-Group-Chat-Recorder.md` หัวข้อ C2 (ยาวเกินกว่าจะย่อ)

### 3.2 รีวิวความปลอดภัยของ Webhook

```
ช่วยรีวิวโค้ด webhook ที่เพิ่งเขียน ตอบเป็นข้อ ๆ ว่าทำครบหรือไม่ ถ้าไม่ครบให้แก้ให้
1. ถ้าฐานข้อมูลล่ม /webhook ยังตอบ 200 หรือไม่
2. ถ้า signature ไม่ถูกต้อง จะตอบ status อะไร
3. express.json() ถูกวางไว้ครอบ /webhook หรือเปล่า
4. ถ้าดึงชื่อผู้ส่งล้มเหลว ข้อความยังถูกบันทึกอยู่ไหม
5. ถ้า LINE ส่ง event เดิมซ้ำ จะเกิดข้อมูลซ้ำในตารางหรือไม่
6. มีการ log ค่า token หรือ secret ออก console ที่ไหนบ้าง
```

### 3.3 สรุปว่าคุยเรื่องอะไร

```
อ่านข้อความทั้งหมดในตาราง line_messages ของวันนี้ เฉพาะกลุ่ม <groupId>
แล้วสรุปว่ากลุ่มคุยเรื่องอะไรกันบ้าง แบ่งเป็นหัวข้อ
พร้อมระบุว่าใครเป็นคนเสนอประเด็นไหน ตอบภาษาไทยไม่เกิน 15 บรรทัด
```

### 3.4 วิเคราะห์พฤติกรรมกลุ่ม

```
วิเคราะห์จากตาราง line_messages เฉพาะกลุ่ม <groupId>
1. ใครพูดเยอะสุด 3 อันดับ (จำนวนข้อความและสัดส่วนเปอร์เซ็นต์)
2. ช่วงเวลาไหนของวันที่กลุ่มคุยกันคึกคักที่สุด
3. ความยาวข้อความเฉลี่ยของแต่ละคน บอกอะไรเกี่ยวกับสไตล์การสื่อสารบ้าง
แสดง SQL ที่ใช้ให้ผมดูด้วย
```

### 3.5 หางานที่มอบหมาย

```
ค้นในบทสนทนาของกลุ่ม <groupId> ช่วง <ช่วงเวลา>
ว่ามีการนัดหมาย มอบหมายงาน หรือมีใครรับปากว่าจะทำอะไรบ้าง
สรุปเป็นตาราง: ใครรับผิดชอบ / งานอะไร / กำหนดเมื่อไหร่ / ข้อความต้นทาง
เอาเฉพาะที่ชัดเจน ห้ามเดาเอง ถ้าไม่ชัดให้ระบุว่า "ไม่ชัดเจน"
```

### 3.6 หาประเด็นค้าง

```
จากบทสนทนาของกลุ่ม <groupId> วันนี้ มีเรื่องอะไรที่คุยแล้วยังไม่ได้ข้อสรุป
หรือรอการตัดสินใจจากใครอยู่ เรียงตามความเร่งด่วน พร้อมบอกว่าใครควรเป็นคนตัดสินใจ
```

### 3.7 สรุปแล้วส่งกลับเข้ากลุ่ม

```
สรุปบทสนทนาวันนี้ของกลุ่ม <groupId> ให้กระชับไม่เกิน 10 บรรทัด
ขึ้นต้นว่า "สรุปประชุมกลุ่มวันนี้" ตามด้วยประเด็นสำคัญเป็นข้อ ๆ
และปิดท้ายด้วยรายการงานที่มีคนรับไปทำ
ห้ามใช้ markdown แสดงข้อความให้ผมอ่านยืนยันก่อน แล้วจึงส่งเข้ากลุ่ม
```

### 3.8 Flex สรุปประชุม

```
สร้างสรุปสถิติกลุ่มวันนี้เป็น Flex Message แบบ bubble ขนาด mega
- ส่วนหัวพื้นหลังสีน้ำเงินเข้ม #0C1628 ตัวอักษรขาว หัวข้อ "สรุปประชุมกลุ่มวันนี้"
- จำนวนข้อความรวม / Top 3 คนที่คุยเยอะสุด / ประเด็นเด่น 3 เรื่อง / งานที่มีคนรับไปทำ
- footer ตัวเล็กสีเทา "สร้างอัตโนมัติโดย AI Agent"
altText: "สรุปประชุมกลุ่มวันนี้"
แสดง JSON ให้ผมตรวจก่อน แล้วส่งเข้ากลุ่ม
```

### 3.9 รายงาน HTML ประจำสัปดาห์

```
ดึงข้อมูลจาก line_messages ของกลุ่ม <groupId> ย้อนหลัง 7 วัน

- timeline หัวข้อสนทนาสำคัญรายวัน
```

## 4. รายงานธุรกิจอัตโนมัติ (Workshop 5)

### 4.1 สรุปยอดขายรายวัน

```
จากตาราง sales_orders ช่วยสรุปยอดขายของ <วันที่ หรือ "เมื่อวาน">
- ยอดขายรวม จำนวนบิล ยอดเฉลี่ยต่อบิล
- แยกตามสาขา เรียงมากไปน้อย / แยกตามช่องทางขาย / สินค้าขายดี 5 อันดับ
- เทียบกับวันก่อนหน้าเป็นเปอร์เซ็นต์
ไม่นับ status = 'cancelled' แสดงตัวเลขแบบมี comma และหน่วยบาท
```

### 4.2 Anomaly Detection

```
ช่วยตรวจหารายการที่น่าสงสัยหรือผิดปกติในยอดขาย <วันที่>
คิดเกณฑ์ตรวจสอบเองอย่างน้อย 4 แบบ เช่น ยอดต่อบิลสูงผิดปกติ
ราคาต่อหน่วยต่างจากปกติของสินค้าเดียวกันมาก ยอดติดลบ และรายการที่ดูเหมือนคีย์ซ้ำ
อธิบายเกณฑ์ที่ใช้ แสดง SQL บอกว่าแต่ละรายการน่าจะเกิดจากอะไร
และเสนอว่าควรแก้ไขอย่างไรในทางบัญชี
```

### 4.3 ตรวจ false positive ของเกณฑ์ตัวเอง

```
เกณฑ์ตรวจ anomaly ที่คุณเสนอมา ช่วยประเมินความเสี่ยงที่จะจับผิดเกินจริง (false positive)
ทดสอบเกณฑ์เดียวกันกับข้อมูลทั้ง 30 วัน แล้วบอกว่าแต่ละเกณฑ์จับได้กี่รายการ
ถ้าเกณฑ์ไหนจับเยอะเกินจริง ให้เสนอวิธีปรับให้แม่นขึ้น
```

### 4.4 หา insight เชิงธุรกิจ

```
จากข้อมูล 30 วันในตาราง sales_orders ช่วยหา insight 5 ข้อที่ผู้บริหารควรรู้
พร้อมตัวเลขสนับสนุนทุกข้อ และแยกให้ชัดว่าข้อไหนเป็น "ข้อเท็จจริงจากข้อมูล"
กับข้อไหนเป็น "ข้อสันนิษฐาน" ของคุณ
```

### 4.5 สร้างสคริปต์รายงานอัตโนมัติ

ดู prompt เต็มใน `05-Workshop-5-Capstone-Executive-Report.md` หัวข้อ C1

### 4.6 สร้างไฟล์ .bat + สอนตั้ง Task Scheduler

```
ช่วยสร้างไฟล์ run-daily-report.bat สำหรับ Windows Task Scheduler ที่
- cd เข้าโฟลเดอร์โปรเจกต์ <path>
- รัน npm run daily-report -- --group=<groupId>
- เก็บ log ต่อท้ายไฟล์ logs\daily-report.log พร้อมประทับวันเวลาทุกครั้งที่รัน
แล้วสอนผมตั้ง Task Scheduler ให้รันทุกวัน 08:00 เป็นขั้นตอนที่กดตามได้
ระบุด้วยว่าช่องไหนที่คนมักตั้งพลาดบ่อย
```

### 4.7 Alert-only pattern

```
แก้สคริปต์ daily-report ให้มีโหมด --alert-only
ที่จะส่งข้อความเข้ากลุ่ม "เฉพาะเมื่อ" ตรวจพบรายการผิดปกติเท่านั้น
ถ้าไม่พบให้เขียน log ว่าปกติแล้วจบการทำงาน ไม่ต้องรบกวนกลุ่ม
```

## 4.5 เก็บภาพและไฟล์จากไลน์กลุ่ม (Workshop 6)

### 4.5.1 สร้างระบบเก็บไฟล์

ดู prompt เต็มใน `11-Workshop-6-Media-Archiver.md` หัวข้อ Part D

### 4.5.2 ให้ AI ตรวจว่าออกแบบถูกหลักไหม

```
ระบบเก็บไฟล์จากไลน์กลุ่มที่ผมทำ ช่วยตรวจตามหัวข้อนี้แล้วบอกว่าผ่านหรือไม่ผ่าน
1. ดาวน์โหลดไฟล์ทันทีที่รับ webhook หรือเก็บ messageId ไว้โหลดทีหลัง
2. การโหลดไฟล์บล็อกการตอบ 200 ให้ LINE หรือเปล่า
3. จัดการกรณี contentProvider.type เป็น external หรือยัง
4. วิดีโอและเสียงรอสถานะ transcoding ก่อนโหลดหรือไม่
5. ถ้าโหลดไฟล์ล้มเหลว ข้อความยังถูกบันทึกอยู่ไหม
6. มีการจำกัดขนาดไฟล์สูงสุดหรือยัง
7. storage key มีโอกาสถูกใช้ทำ path traversal ได้ไหม
8. เมื่อผู้ใช้ยกเลิกส่ง ระบบลบไฟล์ออกจาก storage จริงหรือแค่ทำเครื่องหมายในฐานข้อมูล
ข้อไหนไม่ผ่านให้แก้ให้พร้อมอธิบายเหตุผล
```

### 4.5.3 ให้ AI อ่านสลิปและใบเสร็จที่ส่งเข้ากลุ่ม

```
ในตาราง media_files มีภาพสลิปโอนเงินและใบเสร็จที่เก็บจากไลน์กลุ่มไว้
ช่วยเขียนสคริปต์ที่
1. ดึงภาพชนิด image ของช่วงวันที่ที่ระบุออกมาจาก storage
2. ส่งให้โมเดลอ่านข้อความในภาพ (วันที่ จำนวนเงิน ธนาคาร เลขที่อ้างอิง ผู้รับ)
3. บันทึกผลลงตารางใหม่ชื่อ slip_records พร้อมอ้างอิงกลับไปที่ media_files
4. ทำเป็นไฟล์ Excel สรุปรายเดือน
5. ถ้าอ่านไม่ออกให้ทำเครื่องหมายไว้ให้คนตรวจซ้ำ ห้ามเดาตัวเลข
เตือนผมด้วยว่าข้อมูลอ่อนไหวอะไรบ้างที่ไม่ควรส่งออกนอกองค์กร
```

### 4.5.4 นโยบายพื้นที่จัดเก็บ

```
ช่วยประเมินการใช้พื้นที่ของระบบเก็บไฟล์จากตาราง media_files
- ปริมาณเฉลี่ยต่อวันและต่อเดือน แยกตามชนิดไฟล์และตามกลุ่ม
- คาดการณ์ว่าอีก 6 เดือนและ 1 ปีจะใช้พื้นที่เท่าไหร่
- เสนอนโยบายเก็บข้อมูลที่เหมาะสม พร้อมเหตุผล
- บอกว่าถ้าย้ายขึ้น object storage จะมีค่าใช้จ่ายประมาณเท่าไหร่ต่อเดือน
```

## 5. Prompt สำหรับดูแลระบบระยะยาว

### 5.1 นโยบายเก็บข้อมูล

```
ช่วยเขียนสคริปต์ scripts/cleanup.ts ที่ลบข้อความใน line_messages ที่เก่ากว่า <90> วัน
โดยก่อนลบให้สรุปจำนวนที่จะลบและถามยืนยัน (ยกเว้นใส่ --yes)
พร้อม export ข้อมูลที่จะลบเป็น CSV เก็บไว้ในโฟลเดอร์ backups/ ก่อน
```

### 5.2 ตรวจสุขภาพระบบ

```
ช่วยเขียนสคริปต์ตรวจสุขภาพระบบที่รายงานว่า
- ฐานข้อมูลต่อได้ไหม จำนวนแถวในแต่ละตาราง
- ข้อความล่าสุดที่ได้รับจาก LINE เมื่อไหร่ (ถ้าเกิน 24 ชม. ให้เตือนว่า webhook อาจหลุด)
- โควต้าข้อความคงเหลือ ถ้าเหลือน้อยกว่า 20% ให้เตือน
- การส่งข้อความที่ status = failed ใน 7 วันที่ผ่านมา
แล้วส่งผลเข้าไลน์กลุ่มแอดมิน
```

### 5.3 เตรียมโปรเจกต์ขึ้น Render + Neon

```
ผมมีระบบ webhook + PostgreSQL + dashboard (Express + EJS) ที่รันบนเครื่องตัวเองอยู่
ต้องการ deploy ขึ้น Render แผน Starter โดยใช้ Neon เป็นฐานข้อมูล
ช่วยตรวจโปรเจกต์แล้วบอกเป็นข้อ ๆ ว่าต้องแก้อะไรบ้าง โดยดูประเด็นเหล่านี้เป็นอย่างน้อย
1. session เก็บใน memory หรือไม่ (ถ้าใช่ ล็อกอินจะหลุดทุกครั้งที่ deploy ใหม่)
2. cookie ต้องเป็น secure และต้องตั้ง trust proxy หรือไม่ เพราะอยู่หลัง reverse proxy
3. การต่อ PostgreSQL ต้องเปิด SSL และควรใช้ connection string แบบ pooled หรือไม่
4. ตอน build ไฟล์ที่ไม่ใช่ .ts (เช่น view .ejs) จะถูกคัดลอกไปที่ dist หรือไม่
5. path ที่ใช้ __dirname จะเปลี่ยนไปหลัง build หรือเปล่า
6. งานที่เคยตั้งด้วย Windows Task Scheduler ต้องย้ายไปทำอย่างไร
7. ค่า secret ตัวไหนที่ห้ามอยู่ในไฟล์ที่ commit ขึ้น git
แก้ให้ด้วยโดยยังต้องรันในเครื่องแบบเดิมได้เหมือนเดิม (ใช้ env แยกพฤติกรรม ไม่แยกโค้ดสองชุด)
```

### 5.4 ตรวจความพร้อมก่อน deploy

```
ช่วยไล่ตรวจโปรเจกต์นี้ก่อนขึ้น production แล้วสรุปเป็น checklist ว่าอะไรพร้อม อะไรยัง
- ไฟล์หรือค่าใดที่เป็นความลับแล้วเผลอ commit ขึ้น git ไปแล้วบ้าง
- endpoint ใดที่เข้าถึงได้โดยไม่ต้องล็อกอิน และควรเป็นอย่างนั้นจริงหรือไม่
- ฟอร์ม POST ทุกฟอร์มมีการป้องกัน CSRF หรือยัง
- หน้า login มี rate limit กันเดารหัสหรือยัง
- ถ้าฐานข้อมูลล่มกลางทาง ผู้ใช้จะเห็นอะไร และ webhook ยังตอบ 200 อยู่ไหม
เรียงลำดับความสำคัญจากมากไปน้อย และบอกว่าข้อไหนควรแก้ก่อน deploy ข้อไหนแก้ทีหลังได้
```

## หลัก 6 ข้อของ prompt ที่ใช้ได้กับ AI Agent ทุกตัว

1. **บอกบทบาทและบริบท** - "ผมเป็นเจ้าหน้าที่ HR ของบริษัท..." AI จะเลือกน้ำเสียงถูก
2. **ระบุผลลัพธ์เป็นข้อ ๆ** - บอกสี ขนาด ปุ่ม จำนวนบรรทัด ให้ครบ
3. **อ้างชื่อเครื่องมือเมื่อจำเป็น** - "ส่งผ่าน push_flex_message" ชัดกว่า "ส่งเข้าไลน์"
4. **ขอให้แสดงก่อนลงมือ** - "แสดง JSON ให้ผมตรวจก่อน แล้วจึงเรียก tool" (human-in-the-loop)
5. **ระบุข้อห้าม** - "ห้ามใช้ markdown", "ห้าม broadcast โดยไม่ถาม", "ห้ามเดาข้อมูล"
6. **บอกภาษาและรูปแบบวันที่** - "ภาษาไทย ใช้ พ.ศ." กันความสับสน
