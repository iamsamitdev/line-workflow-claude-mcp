## Part A: Rich Menu คืออะไรและมีข้อจำกัดอะไร (5 นาที)

Rich Menu คือเมนูที่ปรากฏด้านล่างหน้าแชทของ OA

สิ่งที่ต้องรู้ก่อนสั่ง AI

| หัวข้อ | รายละเอียด |
| --- | --- |
| ขนาดภาพ | 2500x1686 px (ใหญ่) หรือ 2500x843 px (เตี้ย) |
| ไฟล์ภาพ | JPEG/PNG ไม่เกิน 1 MB |
| จำนวนปุ่ม | สูงสุด 20 พื้นที่ (areas) |
| ชนิด action | `uri`, `message`, `postback`, `datetimepicker`, `richmenuswitch` |
| ข้อสำคัญ | `create_rich_menu` สร้าง "โครง" ได้ แต่ **ภาพต้องอัปโหลดแยก** ผ่าน Content API |

> ในคลาสเราจะสร้างโครง + ตั้งเป็นเมนูหลักด้วย MCP แล้วอัปโหลดภาพผ่าน OA Manager
> เพราะการอัปโหลดภาพต้องใช้ endpoint `api-data.line.me` ซึ่งไม่ได้อยู่ใน MCP ตัวนี้

## Part B: สร้าง Rich Menu เมนูบริการพนักงาน (20 นาที)

### B1. ดูของเดิมก่อน

```
ช่วยแสดง rich menu ทั้งหมดที่มีอยู่ใน LINE OA ของผม ถ้าไม่มีให้บอกว่าไม่มี
```

### B2. สร้างเมนู 6 ช่อง

```
ช่วยสร้าง Rich Menu สำหรับ LINE OA ของบริษัทสยามสมาร์ทเทรด เป็น "เมนูบริการพนักงาน"
ข้อกำหนด
- ขนาด 2500 x 1686 (แบบใหญ่) แบ่งเป็น 6 ช่องเท่า ๆ กัน (3 คอลัมน์ 2 แถว)
- ชื่อเมนู (name): "เมนูบริการพนักงาน v1"
- chatBarText: "เมนูพนักงาน"
- selected: false
- ช่องทั้ง 6 ตามลำดับ ซ้ายไปขวา บนลงล่าง
  1. ประกาศบริษัท     -> action message ส่งข้อความ "ดูประกาศบริษัท"
  2. ขอเอกสาร HR      -> action message ส่งข้อความ "ขอเอกสาร HR"
  3. แจ้งลา/ลาป่วย     -> action message ส่งข้อความ "แจ้งลา"
  4. เบอร์ติดต่อภายใน  -> action message ส่งข้อความ "เบอร์ติดต่อภายใน"
  5. เว็บไซต์บริษัท    -> action uri ไปที่ https://www.itgenius.co.th
  6. ติดต่อฝ่ายบุคคล   -> action uri ไปที่ https://line.me/R/ti/p/@itgenius

ก่อนสร้าง ให้แสดง JSON ที่จะส่งให้ผมตรวจก่อน แล้วอธิบายว่าค่า bounds ของแต่ละช่อง
คำนวณมาจากอะไร แล้วจึงเรียก create_rich_menu
```

**จุดสอน:** ให้ผู้เรียนสังเกตค่า `bounds` ว่า AI คำนวณ 2500/3 = 833 และ 1686/2 = 843 ถูกหรือไม่
นี่คือทักษะสำคัญ: **ตรวจงาน AI ได้ ไม่ใช่เชื่อทุกอย่าง**

### B3. ตั้งเป็นเมนูหลัก

```
ตั้ง rich menu ที่เพิ่งสร้างเป็นเมนูหลัก (default) ของบัญชี
แล้วยืนยันด้วยการแสดงรายการ rich menu ทั้งหมดพร้อมบอกว่าตัวไหนเป็น default
```

### B4. อัปโหลดภาพ (ทำมือ)

**ชุดนี้มีภาพพร้อมใช้ให้แล้ว ไม่ต้องออกแบบเอง**

```
assets/LINE_Rich_Menu_HR_2500x1686.jpg
```

| รายการ | ค่า | ข้อกำหนดของ LINE |
| --- | --- | --- |
| ขนาดภาพ | 2500 x 1686 px | ต้องเป็นขนาดที่ LINE กำหนด ✅ |
| รูปแบบ | JPEG | JPEG หรือ PNG ✅ |
| ขนาดไฟล์ | 666 KB | ไม่เกิน 1 MB ✅ |

ทั้ง 6 ช่องในภาพเรียงตรงกับ prompt ข้อ B2 พอดี (ประกาศบริษัท / ขอเอกสาร HR / แจ้งลา-ลาป่วย /
เบอร์ติดต่อภายใน / เว็บไซต์บริษัท / ติดต่อฝ่ายบุคคล) และเส้นแบ่งการ์ดในภาพตรงกับค่า `bounds`
ที่คำนวณไว้ (คลาดไม่เกิน 5 px จาก 2500 px = ไม่ถึง 0.2% มองไม่เห็นบนมือถือ)

**ขั้นตอนอัปโหลด**

1. เข้า https://manager.line.biz/ > OA ของคุณ > **Rich menu**
2. เลือกเมนูที่สร้างไว้จากข้อ B2 > อัปโหลดภาพ `assets/LINE_Rich_Menu_HR_2500x1686.jpg` > บันทึก
3. เปิดแชทกับบอทในมือถือ **ปิดแล้วเปิดใหม่** จะเห็นเมนูโผล่มา
4. กดปุ่ม "ประกาศบริษัท" บอทต้องตอบรายการประกาศกลับมา (ดูข้อ B4.5)

> 💡 **อยากทำภาพเอง** ใช้ Canva, Figma, PowerPoint หรือให้ AI สร้าง SVG แล้ว export ก็ได้
> ขอแค่ 3 อย่าง: ขนาด 2500 x 1686 px, ไฟล์ไม่เกิน 1 MB และ**เส้นแบ่งช่องอยู่ที่ x = 833, 1666 และ y = 843**
> ให้ตรงกับ `bounds` ที่สั่ง AI สร้างไว้ ไม่งั้นผู้ใช้จะกดโดนช่องข้าง ๆ

> ⚠️ **ภาพกับ bounds เป็นคนละส่วนกันโดยสิ้นเชิง** LINE ไม่ได้ตรวจว่าภาพตรงกับพื้นที่กดหรือไม่
> ถ้าอัปโหลดภาพที่แบ่ง 4 ช่องทับเมนูที่สร้าง bounds ไว้ 6 ช่อง ระบบก็ยอมรับ แต่ผู้ใช้จะกดแล้วงง
> **คนที่ต้องตรวจให้ตรงกันคือเรา ไม่ใช่ LINE และไม่ใช่ AI**

### B4.5 ทำให้ "กดแล้วบอทตอบ" ได้จริง

Rich Menu เป็นแค่ปุ่ม กดแล้ว LINE จะส่งข้อความนั้นเข้า webhook เหมือนผู้ใช้พิมพ์เอง
**ถ้าไม่มีใครรับ ก็จะเงียบ** ฝั่งที่รับอยู่ในโปรเจกต์นี้แล้วที่

`app/src/services/autoReply.ts`

```ts
export const MENU_REPLIES: MenuReply[] = [
  {
    key: 'announcements',                        // ใช้กับ action ชนิด postback (data = menu=announcements)
    keywords: ['ดูประกาศบริษัท', 'ประกาศบริษัท'],  // ใช้กับ action ชนิด message
    reply: () => '...'
  },
  // ...
]
```

การไล่ทดสอบในคลาส (ทำได้แม้ยังไม่มี OA จริง เพราะโหมด MOCK จะพิมพ์คำตอบลง console)

1. เปิดแชท 1:1 กับ OA แล้วกดปุ่ม "ประกาศบริษัท" บอทต้องตอบรายการประกาศกลับมา
2. พิมพ์คำมั่ว ๆ เช่น "สวัสดี" บอทจะตอบข้อความแนะนำเมนูให้ (fallback)
3. ลองกดเพิ่มเพื่อนใหม่ (บล็อกแล้วปลดบล็อก) จะได้ข้อความต้อนรับจาก event `follow`

**ให้ผู้เรียนแก้เอง:** เพิ่มปุ่มที่ 7 "ตารางรถรับส่งพนักงาน" โดยเพิ่ม 1 รายการใน `MENU_REPLIES`
แล้วสั่ง AI สร้าง Rich Menu ใหม่ให้มีช่องที่ 7 ตรงกัน

> **จุดสอนสำคัญ:** ข้อความแชท 1:1 ระบบนี้จงใจ**ไม่บันทึกลงฐานข้อมูล**
> เก็บเฉพาะบทสนทนากลุ่มที่แจ้งความยินยอมไว้แล้ว (ดูหน้า `/groups`)

## Part C: Cross-check บน GPT Codex (15 นาที)

### C1. ตั้งค่า MCP ฝั่ง Codex

Codex CLI ใช้ไฟล์ config เป็น TOML ไม่ใช่คำสั่ง `mcp add`

ไฟล์อยู่ที่

- Windows: `%USERPROFILE%\.codex\config.toml`
- macOS/Linux: `~/.codex/config.toml`

เพิ่มบล็อกนี้

```toml
[mcp_servers.line-bot]
command = "npx"
args = ["-y", "@line/line-bot-mcp-server"]

[mcp_servers.line-bot.env]
NPM_CONFIG_IGNORE_SCRIPTS = "true"
CHANNEL_ACCESS_TOKEN = "โทเคนของคุณ"
DESTINATION_USER_ID = "userIdของคุณ"
```

แล้วเปิด `codex` ใหม่ ตรวจว่าเห็น tool ของ line-bot

## Part D: หลักเขียน prompt ให้ใช้ได้กับ AI Agent ทุกตัว (5 นาที)

ทำ 6 ข้อนี้แล้ว prompt เดียวจะใช้ได้ทั้ง Claude Code, Codex และตัวอื่นในอนาคต

1. **บอกบทบาทและบริบท** - "ผมเป็นเจ้าหน้าที่ HR ของบริษัท..." AI จะเลือกน้ำเสียงถูก
2. **ระบุผลลัพธ์ที่ต้องการเป็นข้อ ๆ** - ไม่ใช่ "ทำ Flex สวย ๆ" แต่บอกสี ขนาด ปุ่ม ให้ครบ
3. **อ้างชื่อเครื่องมือเมื่อจำเป็น** - "ส่งผ่าน push_flex_message" ชัดกว่า "ส่งเข้าไลน์"
4. **ขอให้แสดงก่อนลงมือ** - "ให้แสดง JSON ให้ผมตรวจก่อน แล้วจึงเรียก tool"
5. **ระบุข้อห้าม** - "ห้ามใช้ markdown ในข้อความ text", "ห้าม broadcast โดยไม่ถาม"
6. **บอกภาษาและรูปแบบวันที่** - "ภาษาไทย ใช้ พ.ศ." กันความสับสนของปี

**ตัวอย่างที่ปรับปรุงแล้ว**

| แบบเดิม | แบบที่ดีขึ้น |
| --- | --- |
| "ส่งไลน์บอกวันหยุด" | "ส่งข้อความ text เข้า LINE ถึงผม แจ้งวันหยุดพิเศษวันจันทร์ที่ 10 สิงหาคม 2569 ลงท้ายว่าฝ่ายบุคคล เขียนสุภาพไม่เกิน 5 บรรทัด ไม่ใช้ markdown" |
| "ทำ rich menu ให้ด้วย" | "สร้าง rich menu 2500x1686 แบ่ง 6 ช่องเท่ากัน (3x2) พร้อม bounds ที่คำนวณถูกต้อง แสดง JSON ให้ตรวจก่อนเรียก create_rich_menu" |
