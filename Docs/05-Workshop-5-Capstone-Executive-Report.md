## Part B: Warm-up สั่ง AI วิเคราะห์ผ่าน MCP (10 นาที)

### B1. ยอดขายเมื่อวาน

```
จากตาราง sales_orders ช่วยสรุปยอดขายของเมื่อวาน
- ยอดขายรวม จำนวนบิล ยอดเฉลี่ยต่อบิล
- แยกตามสาขา เรียงจากมากไปน้อย
- แยกตามช่องทางขาย
- สินค้าขายดี 5 อันดับ
- เทียบกับวันก่อนหน้าเป็นเปอร์เซ็นต์
ไม่นับรายการที่ status = 'cancelled'
แสดงตัวเลขแบบมี comma และหน่วยบาท
```

### B2. Anomaly Detection (ไฮไลท์ของช่วงนี้)

```
ช่วยตรวจหารายการที่น่าสงสัยหรือผิดปกติในยอดขายเมื่อวาน
คิดเกณฑ์ตรวจสอบเองอย่างน้อย 4 แบบ เช่น
- ยอดต่อบิลสูงผิดปกติเมื่อเทียบกับค่าปกติ
- ราคาต่อหน่วยที่ต่างจากราคาปกติของสินค้าเดียวกันมาก
- ยอดติดลบหรือค่าที่เป็นไปไม่ได้
- รายการที่ดูเหมือนคีย์ซ้ำ
อธิบายเกณฑ์ที่ใช้ แสดง SQL และบอกว่าแต่ละรายการน่าจะเกิดจากอะไร
พร้อมเสนอว่าควรแก้ไขอย่างไรในทางบัญชี
```

**เฉลย - รายการที่ฝังไว้**

| เลขที่ | ปัญหา | ควรตรวจด้วยเกณฑ์อะไร |
| --- | --- | --- |
| SO-ANOM-001 | ขายแอร์ 40 เครื่องบิลเดียว 596,000 บาท | ยอดต่อบิล > เกณฑ์ (เช่น 300,000) |
| SO-ANOM-002 | หม้อทอด ราคาต่อหน่วย 259,000 (ปกติ 2,590) | ราคาต่อหน่วยเทียบ median ของสินค้าเดียวกัน > 3 เท่า |
| SO-ANOM-003 | ยอดติดลบ -12,500 (บันทึกคืนสินค้าผิดวิธี) | amount < 0 ควรออกใบลดหนี้ ไม่ใช่ยอดขายติดลบ |
| SO-ANOM-004/005 | รายการเดียวกันคีย์ซ้ำ 2 ครั้ง | GROUP BY สาขา/ช่องทาง/พนักงาน/ลูกค้า/สินค้า/จำนวน/ยอด HAVING COUNT(*) > 1 |

ถ้า AI หาได้ครบ 4 แบบ ให้ชมผู้เรียน ถ้าหาได้ไม่ครบให้ถามต่อว่า "มีรายการที่ยอดติดลบไหม" เพื่อชี้ทาง

**จุดสอนสำคัญ:** เกณฑ์ที่ AI คิดขึ้นเองอาจ **จับผิดเกินจริง** (false positive) เช่น
ถ้าเกณฑ์รายการซ้ำหลวมเกินไป (ดูแค่สินค้า+ยอด) จะจับข้อมูลปกติที่บังเอิญเหมือนกันมาด้วย
ให้ผู้เรียนลองปรับเกณฑ์และดูว่าจำนวนที่ตรวจพบเปลี่ยนไปอย่างไร - นี่คือหัวใจของงาน data quality

## Part C: สร้างสคริปต์ daily-report (20 นาที)

### C1. Prompt สร้างสคริปต์

```
สร้างสคริปต์ TypeScript ชื่อ scripts/daily-report.ts สำหรับส่งรายงานยอดขายเข้ากลุ่มไลน์ผู้บริหาร
ไม่ใส่ semicolon เขียน comment ภาษาไทย

สิ่งที่สคริปต์ต้องทำตามลำดับ
1. รับ argument จาก command line
   --date=YYYY-MM-DD   วันที่ของรายงาน (ค่าเริ่มต้น = เมื่อวาน)
   --group=Cxxxx       groupId ปลายทาง (ถ้าไม่ใส่ให้อ่านจาก DEFAULT_GROUP_ID ใน .env)
   --dry-run           ประกอบข้อความและ log แต่ไม่ส่งออกจริง
2. query จาก PostgreSQL ตาราง sales_orders
   - ยอดรวม จำนวนบิล ยอดเฉลี่ยต่อบิล ของวันที่ระบุ (ไม่นับ status cancelled)
   - เทียบกับวันก่อนหน้าเป็นเปอร์เซ็นต์
   - แยกตามสาขาและช่องทาง
3. ตรวจรายการผิดปกติ 4 เกณฑ์: ยอดต่อบิลเกิน 300000, ราคาต่อหน่วยเกิน 3 เท่าของ median
   ของสินค้าเดียวกัน, ยอดติดลบ, รายการซ้ำ
4. ประกอบ Flex Message bubble ขนาด mega
   - หัวสีน้ำเงินเข้ม #0C1628 หัวข้อ "รายงานยอดขายประจำวัน"
   - ยอดรวมตัวใหญ่ พร้อมลูกศรขึ้น/ลงและเปอร์เซ็นต์เทียบวันก่อน
   - ตารางสาขาและช่องทาง
   - ถ้าพบรายการผิดปกติ ให้มีกล่องพื้นหลังแดงอ่อน ขอบแดง แจ้งรายการทั้งหมด
     ถ้าไม่พบให้เป็นกล่องเขียวอ่อนบอกว่าไม่พบรายการผิดปกติ
5. ส่งเข้ากลุ่มด้วย Push API ของ @line/bot-sdk (ไม่ใช่ MCP เพราะสคริปต์รันเองไม่มี AI)
6. พิมพ์สรุปลง console ทุกครั้งเพื่อให้ตรวจ log ย้อนหลังได้
7. ปิด connection pool และ exit code 0 เมื่อสำเร็จ / 1 เมื่อ error

ข้อกำหนดสำคัญ
- ค่าเกณฑ์ต่าง ๆ ต้องอ่านจาก .env ได้ ไม่ hard-code
- ถ้าไม่พบข้อมูลของวันที่ระบุ ให้แจ้งและบอกวันที่ล่าสุดที่มีข้อมูล ไม่ใช่ crash
- ต้องทดสอบด้วย --dry-run ได้โดยไม่ยิง API จริง
```

### C2. ทดสอบ (สำคัญ ห้ามข้าม)

```bash
# 1) ทดสอบแบบไม่ส่งออก ดูตัวเลขก่อน
npm run daily-report -- --dry-run

# 2) เขียนรายงาน HTML เก็บไว้ดูด้วย
npm run daily-report -- --dry-run --html

# 3) ระบุวันที่ที่มี anomaly ชัด ๆ (เมื่อวาน)
npm run daily-report -- --dry-run --date=2026-08-08

# 4) พอใจแล้วจึงส่งจริง
npm run daily-report -- --group=<groupId ของกลุ่มผู้บริหาร>
```

## Part D: ตั้งเวลารันอัตโนมัติ (10 นาที)

### D1. เตรียมไฟล์ .bat (Windows)

สร้าง `app/run-daily-report.bat`

```bat
@echo off
cd /d "C:\line-workshop-2026\app"
call npm run daily-report -- --group=Cxxxxxxxxxxxxxxxxxxxx >> logs\daily-report.log 2>&1
```

สร้างโฟลเดอร์ `logs` ก่อน แล้วทดสอบดับเบิลคลิกไฟล์ .bat ดูว่าทำงานได้

> ให้ AI ช่วยก็ได้: *"ช่วยสร้างไฟล์ .bat สำหรับ Windows Task Scheduler ที่เข้าโฟลเดอร์โปรเจกต์
> แล้วรัน npm run daily-report โดยเก็บ log ต่อท้ายไฟล์ logs\daily-report.log พร้อมประทับวันเวลา"*

### D2. ตั้ง Windows Task Scheduler

1. เปิด **Task Scheduler** > **Create Task** (ไม่ใช่ Basic Task)
2. tab **General**
   - Name: `LINE Daily Sales Report`
   - เลือก **Run whether user is logged on or not**
   - ติ๊ก **Run with highest privileges**
3. tab **Triggers** > New
   - Begin the task: On a schedule
   - Daily เวลา **08:00:00** ติ๊ก Enabled
4. tab **Actions** > New
   - Action: Start a program
   - Program/script: `C:\line-workshop-2026\app\run-daily-report.bat`
   - Start in: `C:\line-workshop-2026\app`  ← **ข้อนี้คนลืมบ่อยที่สุด ถ้าไม่ใส่จะหา node_modules ไม่เจอ**
5. tab **Conditions** > ปลด **Start the task only if the computer is on AC power** (สำหรับ notebook)
6. tab **Settings** > ติ๊ก **Run task as soon as possible after a scheduled start is missed**
7. บันทึก แล้วคลิกขวาที่ task > **Run** เพื่อทดสอบทันที

ตรวจว่าสำเร็จ: ดู `logs\daily-report.log`, ดู Last Run Result ต้องเป็น `0x0`, และดูข้อความในไลน์กลุ่ม

### D3. ทางเลือกอื่น และของที่เตรียมไว้ให้แล้ว

| วิธี | เหมาะกับ | วิธีตั้ง |
| --- | --- | --- |
| **Windows Task Scheduler** | เครื่องผู้ใช้/เซิร์ฟเวอร์ Windows (ใช้ในคลาส) | ตามข้างบน |
| **ตัวตั้งเวลาในตัวโปรแกรม** | เมื่อ deploy บน cloud ที่รันค้างตลอด เช่น Render Starter | ตั้ง `ENABLE_SCHEDULER=true` ใน env |
| cron (macOS/Linux) | เซิร์ฟเวอร์ Linux ที่รันเอง | `0 8 * * * cd /path/app && npm run daily-report` |
| GitHub Actions | ไม่มีเซิร์ฟเวอร์เลย | `schedule: - cron: "0 1 * * *"` (UTC) |

**ตัวตั้งเวลาในตัวโปรแกรม** เตรียมไว้ให้แล้วที่ `src/scheduler.ts` เปิดใช้ด้วย 3 ค่านี้

```env
ENABLE_SCHEDULER=true
SUMMARY_CRON=0 18 * * *     # สรุปแชทกลุ่มทุกเย็น 18:00
REPORT_CRON=0 8 * * *       # รายงานผู้บริหารทุกเช้า 08:00
```

เวลาอ้างตามค่า `TZ` (ค่าเริ่มต้น `Asia/Bangkok`) จึงใส่เวลาไทยได้ตรง ๆ ไม่ต้องแปลง UTC

> **จุดสอนที่ควรชี้ให้เห็น:** ตรรกะของงานอยู่ที่ `src/jobs/dailyReport.ts` ที่เดียว
> แต่ถูกเรียกได้ 3 ทาง คือ CLI (`npm run daily-report`), ตัวตั้งเวลาในตัว และปุ่มในหน้า `/sales`
> การแยกตรรกะออกจาก "ทางเข้า" ทำให้ย้ายจาก Task Scheduler ไป cloud ได้โดยไม่ต้องเขียนโค้ดใหม่

**คำเตือนเรื่อง timezone:** cron ของ GitHub Actions ใช้ UTC ต้องลบ 7 ชั่วโมงจากเวลาไทย
(08:00 ไทย = 01:00 UTC) แต่ตัวตั้งเวลาในตัวโปรแกรมและ Task Scheduler ใช้เวลาท้องถิ่นตรง ๆ

## Part E: ต่อยอด (โจทย์ท้าทาย เลือกทำ)

1. **แจ้งเตือนเฉพาะเหตุผิดปกติ** - ทำไว้ให้แล้วเป็นตัวอย่าง ลองรัน
   `npm run daily-report -- --alert-only --dry-run` ดูว่าเมื่อไม่พบ anomaly ระบบจะไม่ส่งเข้ากลุ่ม
   (alert-only pattern ลดเสียงรบกวนผู้บริหาร) แล้วให้ผู้เรียนอ่านโค้ดใน `src/jobs/dailyReport.ts`
   ว่าทำอย่างไร
2. **รายงานสรุปสัปดาห์** - สคริปต์ใหม่ที่รันเช้าวันจันทร์ สรุป 7 วันพร้อมกราฟ HTML แนบลิงก์
3. **เตือนเป้ายอดขาย** - ถ้ายอดสะสมเดือนต่ำกว่าเป้าเกิน 10% ให้ส่งเตือนแยกอีกข้อความ
4. **รวมสองระบบเข้าด้วยกัน** - รายงานเช้าเพิ่มบรรทัด "งานค้างจากกลุ่มปฏิบัติการ N รายการ"
   ดึงจาก `group_tasks` (ใช้ข้อมูลทั้ง 2 Workshop ในรายงานเดียว)
