## จุดเสี่ยงและแผนสำรอง (สำคัญที่สุดของเอกสารนี้)

### เสี่ยงที่ 1: MCP ต่อไม่ติด (Day 1 Session 2)

**สาเหตุอันดับ 1: Node เวอร์ชันต่ำกว่า 22**

- แผนป้องกัน: ให้ทุกคนพิมพ์ `node -v` ลง chat ของ Zoom ตอนต้นคาบ เห็นปัญหาก่อนเสียเวลา
- แผนสำรอง: ผู้ที่ยังแก้ไม่ได้ ให้ดูจอผู้สอนก่อน แล้วช่วยแก้ตอนพักเบรก
- ห้ามหยุดคลาสรอคนเดียวเกิน 5 นาที ให้เดินหน้าและตามเก็บทีหลัง

### เสี่ยงที่ 2: โควต้าข้อความหมด (Day 1 Workshop 1)

Free plan = 200 ข้อความ/เดือน ซึ่งพอสำหรับคลาสถ้าไม่ประมาท

- **ห้าม broadcast ซ้ำเพื่อทดสอบ** ย้ำก่อนเริ่ม C4
- ให้ทุกคนรัน `get_message_quota` ตอนต้นและตอนท้าย Workshop เพื่อเห็นว่าใช้ไปเท่าไหร่
- ถ้าใครหมดโควต้า ให้ใช้ dashboard โหมด MOCK ทำต่อได้ (ไม่ต้องรอเดือนใหม่)

### เสี่ยงที่ 3: เชิญบอทเข้ากลุ่มไม่ได้ (Day 2 Workshop 3)

- ตรวจ "Allow bot to join group chats" **ล่วงหน้าตอน Day 1** ตอนท้ายคาบ ไม่ใช่รอ Day 2
- แผนสำรอง: `npm run seed:chat` + หน้า `/simulator` ทำ Workshop 4-5 ต่อได้ครบ 100%

### เสี่ยงที่ 4: tunnel ล่มหรือ URL เปลี่ยน (Day 2 Workshop 3)

หลักสูตรนี้ใช้ **cloudflared เป็นตัวหลัก** (ngrok ตัดแพลนฟรีเหลือ 2 ชม./session ตั้งแต่ต้นปี 2026)

- ย้ำก่อนเริ่ม: **เปิด tunnel ทิ้งไว้ตลอดคาบ อย่าปิด** เพราะ URL จะเปลี่ยนและต้องไปแก้ใน Console ใหม่
- ผู้สอนควรใช้ **named tunnel + โดเมนของตัวเอง** จะได้ URL คงที่ ไม่ต้องแก้ตอนสาธิต
- แผนสำรองตามลำดับ: `ngrok http 3000` > `npx localtunnel --port 3000` > `localhost.run`
- แผนสำรองสุดท้าย: ผู้สอนแชร์ผลจากเครื่องตัวเองให้ดูร่วมกัน แล้วผู้เรียนใช้ `/simulator` ทำ Workshop 4-5 ต่อ

### เสี่ยงที่ 5: เวลาไม่พอที่ Capstone (Day 2 22:15)

ถ้าถึง 22:35 แล้วยังไม่มีใครได้สคริปต์ ให้ตัดตามลำดับนี้

1. ตัด Part B3 (หา insight) - ไม่กระทบผลลัพธ์ปลายทาง
2. ให้ผู้เรียน **ใช้สคริปต์ที่แจกในชุดไฟล์** (`app/scripts/daily-report.ts`) แทนการให้ AI เขียนเอง
   แล้วเน้นสอนที่การอ่านโค้ดและตั้ง Task Scheduler ซึ่งเป็นผลลัพธ์หลักของคาบ
3. Part D (Task Scheduler) **ห้ามตัด** เพราะเป็น moment ปิดคอร์ส

## ประเด็นที่ผู้เรียนถามบ่อย (เตรียมคำตอบไว้)

**"ทำไมบอทอ่านแชทเก่าไม่ได้ Telegram ทำได้"**
LINE ออกแบบ Messaging API เป็น event-driven เพื่อความเป็นส่วนตัว ไม่มี API ดึงประวัติเลย
Telegram มี `getUpdates` และ bot API ที่ต่างออกไป นี่คือข้อจำกัดของแพลตฟอร์ม ไม่ใช่ของโค้ดเรา

**"เก็บแชทกลุ่มพนักงานผิดกฎหมายไหม (PDPA)"**
ต้องมีฐานในการประมวลผล ที่ปฏิบัติง่ายที่สุดคือความยินยอมที่แจ้งชัด บวกกับ
1) แจ้งวัตถุประสงค์ 2) เก็บเท่าที่จำเป็น 3) กำหนดระยะเวลาเก็บ 4) ให้สิทธิ์ขอลบ
แนะนำให้หารือฝ่ายกฎหมาย/HR ขององค์กรก่อนใช้จริง และเริ่มจากกลุ่มที่ทีมยินยอมพร้อมกัน

**"AI จะเห็นข้อมูลบริษัทเราไหม"**
เมื่อใช้ MCP ข้อมูลที่ AI query จะถูกส่งไปที่โมเดล ดังนั้นต้อง
1) จำกัดด้วย read-only user 2) ไม่ให้ตารางที่มีข้อมูลอ่อนไหวอยู่ใน schema เดียวกัน
3) พิจารณาใช้ view ที่ mask ข้อมูลไว้แล้ว 4) อ่านนโยบายการเก็บข้อมูลของผู้ให้บริการโมเดล

**"ต้องจ่ายค่า API เท่าไหร่"**
Claude Code รวมอยู่ในแพลน Pro/Max อยู่แล้ว
`ANTHROPIC_API_KEY` สำหรับสคริปต์สรุปเป็นค่าใช้จ่ายแยกตามการใช้ (ประมาณหลักสตางค์ถึงหลักบาทต่อการสรุป 1 ครั้ง)
LINE Messaging API ฟรี 200 ข้อความ/เดือน แพลนที่สูงขึ้นเริ่มหลักร้อยบาท/เดือน

**"เอาไปใช้กับ Slack / Microsoft Teams ได้ไหม"**
ได้และง่ายกว่า เพราะ Slack และ Teams มี API อ่านประวัติแชทได้จริง
สถาปัตยกรรมเดิมใช้ได้ทั้งหมด เพียงเปลี่ยนขาเข้า/ขาออก

## โมดูลเสริม: Workshop 6 Media Archiver

หลักสูตร 2 วันเดิมเต็มอยู่แล้ว โมดูลนี้จึงออกแบบให้เลือกใช้ได้ 3 แบบ

| แบบ | วิธีสอน | เวลา |
| --- | --- | --- |
| A. ต่อท้าย Workshop 3 | สอนเป็นส่วนขยายของ webhook เดิม ตัด Part D (prompt) ออก ให้ใช้โค้ดที่แจก | +20 นาที |
| B. แทน Cross-check Codex ของ Day 2 | ถ้าห้องส่วนใหญ่ไม่มีบัญชี ChatGPT Plus โมดูลนี้ให้คุณค่ามากกว่า | 30 นาที |
| C. คลาสวันที่ 3 หรือคอร์สต่อยอด | สอนเต็มทั้ง 5 Part พร้อมเรื่อง object storage และ OCR สลิป | 60-90 นาที |

**แนะนำแบบ A สำหรับรอบแรก** เพราะเป็นจุดที่ผู้เรียนจะ "ร้องอ๋อ" ดังที่สุด
และใช้เวลาน้อยที่สุด

**Moment ที่ควรจัดให้เกิดในคลาส:** ให้ผู้เรียนส่งรูปเข้ากลุ่ม รอระบบเก็บ
แล้ว **ลบรูปนั้นออกจากแชท** จากนั้นเปิดหน้า `/media` ให้ดูว่ารูปยังอยู่ครบ
ตามด้วยการสาธิต unsend เพื่อแสดงว่าระบบเคารพเจตนาผู้ใช้ด้วย
สองอย่างนี้ต่อกันจะสื่อสารทั้งคุณค่าและความรับผิดชอบพร้อมกัน

**ประโยคที่ใช้ขายคอร์สได้:** "หมดปัญหาภาพและไฟล์ในไลน์กลุ่มหมดอายุ กดโหลดไม่ได้"
แต่ต้องมีวงเล็บต่อท้ายเสมอว่า *(นับจากวันที่ติดตั้งระบบเป็นต้นไป)*
เพราะระบบไม่ได้กู้ไฟล์เก่าที่หมดอายุไปแล้ว ถ้าสื่อสารไม่ครบจะเจอ complaint แน่นอน
