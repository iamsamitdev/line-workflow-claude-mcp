## Part A: เชื่อม Postgres MCP (5 นาที)

```cmd
claude mcp add postgres-linechat ^
  -- npx -y @modelcontextprotocol/server-postgres postgresql://postgres:รหัสผ่าน@localhost:5432/linechat
```

macOS/Linux เปลี่ยน `^` เป็น `\`

ตรวจด้วย `/mcp` ต้องเห็นทั้ง `line-bot` และ `postgres-linechat` เป็น connected

> **แนวปฏิบัติสำคัญ:** ในระบบจริงให้สร้าง PostgreSQL user แบบ **read-only** สำหรับ MCP
> AI จะอ่านได้แต่แก้/ลบข้อมูลไม่ได้
>
> ```sql
> CREATE USER ai_reader WITH PASSWORD 'xxxx';
> GRANT CONNECT ON DATABASE linechat TO ai_reader;
> GRANT USAGE ON SCHEMA public TO ai_reader;
> GRANT SELECT ON ALL TABLES IN SCHEMA public TO ai_reader;
> ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO ai_reader;
> ```

## Part B: 6 prompt วิเคราะห์บทสนทนา (15 นาที)

ทำตามลำดับ ยากขึ้นเรื่อย ๆ

### B1. สรุปว่าคุยเรื่องอะไร

```
อ่านข้อความทั้งหมดในตาราง line_messages ของวันนี้
แล้วสรุปว่ากลุ่มคุยเรื่องอะไรกันบ้าง แบ่งเป็นหัวข้อ
พร้อมระบุว่าใครเป็นคนเสนอประเด็นไหน
ตอบเป็นภาษาไทย ไม่เกิน 15 บรรทัด
```

### B2. วิเคราะห์พฤติกรรมกลุ่ม

```
วิเคราะห์จากตาราง line_messages เฉพาะกลุ่ม <ใส่ groupId ของคุณ>
1. ใครพูดเยอะสุด 3 อันดับ (จำนวนข้อความและสัดส่วนเปอร์เซ็นต์)
2. ช่วงเวลาไหนของวันที่กลุ่มคุยกันคึกคักที่สุด
3. ความยาวข้อความเฉลี่ยของแต่ละคน บอกอะไรเกี่ยวกับสไตล์การสื่อสารบ้าง
แสดง SQL ที่ใช้ให้ผมดูด้วย
```

**จุดสอน:** สังเกตว่า AI เขียน SQL อย่างไร นี่คือวิธีเรียน SQL ที่เร็วที่สุด - อ่านของคนที่เขียนเก่ง

### B3. ติดตามงาน (ใช้งานจริงในทีมได้ทันที)

```
ค้นในบทสนทนาของกลุ่ม <groupId> วันนี้ ว่ามีการนัดหมาย มอบหมายงาน
หรือมีใครรับปากว่าจะทำอะไรบ้าง
สรุปเป็นตาราง: ใครรับผิดชอบ / งานอะไร / กำหนดเมื่อไหร่ (ถ้าระบุ) / ข้อความต้นทาง
เอาเฉพาะที่ชัดเจน ห้ามเดาเอง ถ้าไม่ชัดให้ระบุว่า "ไม่ชัดเจน"
```

### B4. หาประเด็นที่ยังตกลงกันไม่ได้

```
จากบทสนทนาวันนี้ มีเรื่องอะไรที่คุยแล้วยังไม่ได้ข้อสรุป หรือรอการตัดสินใจจากใครอยู่
เรียงตามความเร่งด่วน พร้อมบอกว่าใครควรเป็นคนตัดสินใจ
```

### B5. สรุปแล้วส่งกลับเข้ากลุ่ม (ไฮไลท์)

```
สรุปบทสนทนาวันนี้ของกลุ่ม <groupId> ให้กระชับไม่เกิน 10 บรรทัด
ขึ้นต้นว่า "สรุปประชุมกลุ่มวันนี้" ตามด้วยประเด็นสำคัญเป็นข้อ ๆ
และปิดท้ายด้วยรายการงานที่มีคนรับไปทำ
ห้ามใช้ markdown เพราะ LINE ไม่รองรับ
แสดงข้อความให้ผมอ่านยืนยันก่อน แล้วจึงส่งเข้ากลุ่มด้วย push_text_message
```

### B6. Flex Message รายงานสวยงาม

```
สร้างสรุปสถิติกลุ่มวันนี้เป็น Flex Message แบบ bubble ขนาด mega
- ส่วนหัวพื้นหลังสีน้ำเงินเข้ม #0C1628 ตัวอักษรขาว หัวข้อ "สรุปประชุมกลุ่มวันนี้"
- แสดงจำนวนข้อความรวม
- Top 3 คนที่คุยเยอะสุด (ชื่อและจำนวน)
- ประเด็นเด่น 3 เรื่อง
- รายการงานที่มีคนรับไปทำ
- footer ตัวเล็กสีเทาว่า "สร้างอัตโนมัติโดย AI Agent"
altText: "สรุปประชุมกลุ่มวันนี้"
แสดง JSON ให้ผมตรวจก่อน แล้วส่งเข้ากลุ่มด้วย push_flex_message
```

> เทียบผลลัพธ์กับฟังก์ชัน `flexDailySummary()` ในไฟล์ `app/src/services/flex.ts`
> ของชุด workshop ว่าคิดเหมือนกันหรือไม่

### ลำดับการสาธิตที่แนะนำ (5 นาที)

1. `/summaries` เลือกกลุ่ม เลือกวันนี้ กด **สรุปด้วย AI**
2. ดูข้อความสรุปที่ได้ แล้วไปดู `/tasks` จะเห็นว่างานถูกสกัดเข้ามาให้แล้ว
3. กลับมา `/summaries` กด **ทดสอบ dry-run** แล้วดูใน `/logs`
4. กด **ส่งสรุปเข้ากลุ่ม** จริง แล้วดูในมือถือ
5. `/tasks` กดปิดงานที่ทำเสร็จแล้ว 1 รายการ แล้วกด **ส่งเตือน**

### สองจุดออกแบบที่ควรอธิบาย

**1. โหมด MOCK และ dry-run**

- `MOCK_LINE=true` ใน `.env` = ระบบทำงานครบทุกอย่างแต่ไม่ยิง LINE API
  ทำให้ทดสอบ dashboard ได้โดยไม่เสียโควต้าและไม่ต้องมี OA
- ปุ่ม dry-run = ประกอบข้อความจริง บันทึก log จริง แต่ไม่ส่งออก
- ระบบ automation ที่ดีต้องมีทั้งสองอย่าง มิฉะนั้นการทดสอบจะรบกวนคนในกลุ่มจริง

**2. AI มี fallback**

`app/src/services/summary.ts` ทำงาน 2 แบบ

- ถ้าตั้ง `ANTHROPIC_API_KEY` ใน `.env` จะเรียก Claude API ให้สรุปและสกัดงาน (คุณภาพดีกว่ามาก)
- ถ้าไม่ได้ตั้ง จะใช้ตัวสรุปแบบ rule-based ในเครื่อง (นับสถิติ + จับ pattern คำมอบหมายภาษาไทย)

จุดสอน: ระบบที่ดีต้องไม่ล้มทั้งระบบเพราะขาด API key เดียว - ให้ degrade แต่ยังทำงานได้

## Part D: prompt ให้ AI ต่อยอด Dashboard เอง (โจทย์ท้าทาย)

```
ในโปรเจกต์นี้มี Admin Dashboard เขียนด้วย Express + EJS อยู่แล้ว
ช่วยเพิ่มหน้าใหม่ /keywords ที่แสดง

1. คำที่ถูกพูดถึงบ่อยที่สุด 20 คำในกลุ่มที่เลือก (ตัดคำช่วยภาษาไทยออก)
2. กราฟแสดงจำนวนครั้งที่พบคำ 10 อันดับแรก ด้วย Chart.js
3. ช่องค้นหาที่กดคำแล้วเด้งไปหน้า /messages พร้อม filter คำนั้น

ให้เขียนตามสไตล์เดิมของโปรเจกต์
- service อยู่ใน src/services/ route อยู่ใน src/routes/admin.ts view อยู่ใน src/views/
- ใช้ asyncRouter เหมือน route อื่น
- ไม่ใส่ semicolon comment ภาษาไทย
- เพิ่มลิงก์ในเมนู src/views/partials/nav.ejs ด้วย
รันแล้วต้องผ่าน npm run typecheck
```
